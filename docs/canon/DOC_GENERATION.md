# Канон документации курса

Источник правды для теории, домашек, моков и сайта.
Актуально: сентябрь 2026.

Даты в материалах — **месяц и год**, не число дня. Не пишите прогресс
читателя («пройдено», «сегодня»). Без персональных данных.

Сайт: MkDocs Material → GitHub Pages. EPUB не собираем.

---

## 0. Руками с нуля (жёсткое правило)

Агент **не** делает за разработчика «мелочи в фоне»: не создаёт заранее
каркасы приложений, `pyproject.toml`, CI, линтеры, структуру пакетов,
smoke-тесты «чтобы уже было».

Порядок:

1. объяснить **зачем** (архитектура, модуль, либа, линтер);
2. дать команду / шаг, который печатает и запускает **сам** разработчик;
3. разобрать результат;
4. только потом следующий шаг.

Это относится к Harbor, drills, git, Docker, линтерам (что это и зачем),
выбору зависимостей. Исключение: готовый **сайт курса** как учебник —
его читают; локальный `mkdocs serve` разработчик поднимает сам по инструкции.

**Эталоны:** в git **после** сдачи и ревью задания — не раньше
(`docs/solutions/`). До этого — только ревью в чате, без подглядывания.

---

## 1. Для кого

Читатель готовится к middle / middle+ Python backend (рынок РФ + крупные
компании). Текст должен помочь **закрыть пакет и перечитать**, не отметить
тему буллетами.

Стиль: Ильяхов / Сарычева + учебная ясность. Связный текст ≠ вода.

---

## 1a. Цельность теории (сквозная нить)

Модуль — не россыпь фактов, а **одна история** (обычно домен Harbor:
переговорки). Факты — ступени сюжета: каждый блок отвечает на вопрос
«зачем это сейчас в этой истории».

У модуля в `index.md`:

1. **Сквозная нить** — 3–6 предложений: герой/задача, что умеем в конце;
2. **Откуда пришли** — мост от предыдущего модуля;
3. **Куда уходим** — мост к следующему.

У главы в начале (после заголовка):

1. **Мост** — «в прошлой главе… → здесь… → дальше…»;
2. **Вопрос сюжета** — одна фраза, на которую отвечает вся глава.

Запрещено:

- список фич языка / API без задачи («ещё вот `X`, ещё вот `Y`»);
- глава, которую можно прочитать с конца без потери смысла сюжета;
- «Под капотом» только как синтаксис — нужна **модель** (что происходит
  в голове машины / в данных).

Порядок мысли в главе:

1. мост + вопрос сюжета;
2. зачем на собесе / в проде;
3. словарь (RU + EN + на пальцах);
4. руками → принято;
5. пример с входом/выходом или прогоном;
6. ловушки / до-после;
7. применение в работе;
8. мини-голос;
9. домашка **этого** пакета.

---

## 2. Язык

- Основной язык — **русский**.
- Термин по-русски; английский в скобках при первом появлении.
- Англицизм без пояснения не оставлять.
- Домашки — полностью по-русски; в шапке: что сдать (код / текст / Big O).

---

## 3. Руками → принято

Где stdlib/фреймворк прячет протокол:

1. ручной вариант;
2. принятый;
3. фраза: что закрывает автоматика и чего не умеет.

На алгоритмической секции часто ждут руки. На IDE — pytest / FastAPI как принято.

---

## 4. Обязательные блоки хорошей главы

| Блок | Зачем |
|------|--------|
| С собесов | где звучит, типичный провал |
| Словарь | RU + EN + на пальцах |
| Под капотом | упрощённая модель |
| Каркас + вход | без голых скелетов |
| До / после | плохой → хороший |
| Применение | 3–5 буллетов |
| Мини-голос | 4–6 строк |
| Домашка | ссылка на пакет |

---

## 5. Каркас кода только с данными

Рядом: маленький вход, ожидаемый выход или прогон, фраза что значат поля.

---

## 6. Книги и копирайт

- PDF **не** в git.
- В каталоге и в главах: **автор, название, издание/год** (ISBN если есть) —
  как на обложке/титуле, **не** имя файла и **не** путь на диске.
- При отсылке: **глава / § / страница** + пересказ своими словами.
- Каталог: [books.md](../reference/books.md).
- Verbatim из книг — запрещён.

---

## 7. Домашки

- 3–4 задания low/medium + несколько hard «вернуться позже».
- Разбор чужого кода — отдельным пунктом.
- Пока задание не сдано — эталона в репо нет (ревью в чате).
- После ревью — эталон в `docs/solutions/` (коротко: идея + края + ошибки).
- Моки — срезы по материалу (`docs/mocks/`), не задачи из Harbor.

---

## 8. Смешение тем

Если обучение лучше идёт пакетом (async + Postgres + git) — так и генерируем
навигацию. Не врать «изолированный день», если в главе две темы: явно назвать обе.
