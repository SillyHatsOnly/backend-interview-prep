# Capstone · Harbor

Сквозной проект на все модули. Не «домашка недели», а **одна система**,
которую наращиваете полгода.

Моки курса с Harbor **не смешиваем**: мок — срез знаний по пройденному
материалу (чужой каркас / устный блок). Harbor — длинная практика стека.

## Домен · переговорки в компании

Единая метафора на полгода: **бронирование переговорных комнат**.

База:

- комната: вместимость, этаж/площадка, удобства (проектор, видеосвязь…);
- бронь: интервал времени, число участников, кто заказал;
- аллокатор: подобрать комнату под constraints или отказать при конфликте.

Усложнения **по слоям** (не всё сразу):

| Слой | Примеры фич |
|------|-------------|
| 1 | вместимость + пересечение интервалов |
| 2 | теги удобств (нужен projector) |
| 3 | иерархия площадок (офис → этаж → крыло) |
| 4 | иерархия заказчиков / отделов |
| 5 | приоритеты (exec > team), вытеснение или waitlist |
| 6 | повторные слоты, буфер между встречами, ACL «только свой этаж» |

В публичном коде — вымышленная компания, без реальных ФИО и секретов.

### С собесов (зачем этот домен)

На applied-секциях часто дают каркас «подбор под ограничения + тесты».
Переговорки дают те же мышцы, что номер в гостинице: интервалы, capacity,
приоритеты — но ближе к корпоративному backend.

---

## Продукт в одном абзаце

> **Harbor** — сервис бронирования переговорок: каталог комнат, поиск,
> бронирование без пересечений, идемпотентные API, фоновые уведомления
> («комната подтверждена»). Postgres, поиск (Elastic или этап `ILIKE`),
> FastAPI+asyncio, `docker compose`. В конце — маленький Go-воркер.

Репозиторий: [SillyHatsOnly/harbor-capstone](https://github.com/SillyHatsOnly/harbor-capstone)
(public). В курс — только спеки и чеклисты.

**Типы:** Pyright вводится **руками** в Harbor (что такое type checker / линтер,
зачем, как поставить) — не «уже лежит в pyproject от агента».

Репозиторий продукта создаёте **с нуля** под руководством в чате. Готовый
каркас от агента не является стартовой точкой обучения.

## Наращивание по модулям

| Модуль | Что появляется в Harbor |
|--------|-------------------------|
| M0 | пустой git-репо **своими** руками; README; первые договорённости |
| M1 | модели + pyright — после разбора «зачем линтер/типы» |
| M2–M3 | `allocate`: capacity + time overlap; heap/waitlist — слой приоритетов |
| OS-фон | процесс воркера, FD, блокирующий I/O |
| M4 | async API, семафор, без `time.sleep` |
| M5 | async pytest, фикстуры |
| M6 | Postgres: комнаты/брони, индексы по времени, txn, lost update |
| M7 | FastAPI: search / book / cancel; idempotency-key |
| M8 | поиск по комнатам; Redis optional |
| M9 | compose + restart |
| M10 | optional kind |
| M11 | Go: notify «бронь создана» |

Иерархии заказчиков и приоритеты — после работающего allocate по времени
(не раньше M3–M4 домена).

Git accidents — на копии ветки Harbor, не на `main` курса.

## MVP (после M3–M5 домена, не «календарный месяц»)

1. Модели комнат и броней + pyright clean.
2. `allocate(rooms, request) -> room | error` с пересечением интервалов.
3. Тесты: конфликт времени, нехватка вместимости, первый подходящий.
4. Позже: HTTP `POST /bookings` + `GET /rooms`.

## Definition of done (конец горизонта)

- [ ] Аллокатор + хотя бы один слой «сложности» (удобства или приоритет)
- [ ] Async API + async pytest
- [ ] Postgres + индексы по интервалам + транзакция брони
- [ ] compose up с нуля по README
- [ ] Pyright без ошибок на domain/api
- [ ] Поиск или явный план миграции на Elastic
- [ ] Go-воркер или осознанный defer
- [ ] README: как бежать / тестить / типы проверять
