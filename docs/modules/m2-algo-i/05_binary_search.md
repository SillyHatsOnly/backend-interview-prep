# 05 · Бинарный поиск и левая граница

**Мост:** два указателя из [главы 03](./03_pointers_window.md) отбрасывали по
одному краю, а стек из [главы 04](./04_stack.md) хранил незавершённую
историю. Бинарный поиск снова держит две границы, но сравнение с серединой
позволяет удалить сразу половину кандидатов. После этой главы все приёмы M2
сойдутся в домашке, а в M3 идея явного инварианта перейдёт к обходам графа.

**Вопрос сюжета:** как отбрасывать половину отсортированного списка и каждый
раз доказывать, что ответ остался внутри границ?

### С собесов

Обычно просят написать поиск точного значения, найти первую позицию не
меньше заданного или объяснить вечный цикл. Ошибка почти всегда не в формуле
середины, а в смешении двух договорённостей: входит ли правая граница в
область поиска и остаётся ли `mid` кандидатом после сравнения.

---

## Словарь

- **Бинарный поиск (binary search)** — поиск, который по результату проверки
  середины отбрасывает одну из половин упорядоченного пространства.
- **Полуинтервал (half-open range)** `[lo, hi)` включает `lo`, но не включает
  `hi`. Его длина равна `hi - lo`, а пустое состояние записывается `lo == hi`.
- **Инвариант (invariant)** — утверждение о границах, которое верно до цикла
  и сохраняется после каждой итерации.
- **Левая граница (lower bound)** — первая позиция, где значение не меньше
  заданного; если такой позиции нет, ответ равен длине списка.

---

## Сначала обязательное условие: порядок

Список должен быть отсортирован по тому же признаку, с которым сравнивают
`target`. Если `nums[mid] < target`, только сортировка позволяет заключить,
что все элементы левее тоже меньше и их можно отбросить.

```text
отсортировано: [1, 3, 5, 7, 9]
                    ▲
                  mid = 5

target = 8:
[1, 3, 5] точно не подходят ──► остаётся [7, 9]

не отсортировано: [9, 1, 5, 3, 7]
середина 5 ничего не говорит о том,
где находятся значения меньше и больше
```

Бинарный поиск на неотсортированном списке не становится «примерно
правильным». Он теряет доказательство, поэтому может пропустить существующий
ответ.

---

## Точный поиск в полуинтервале

Договоримся, что область возможного ответа — `[lo, hi)`.

## Под капотом: инвариант границ

Инвариант точного поиска: **если `target` присутствует и ещё не найден, его
индекс лежит в `[lo, hi)`**.

- До цикла это весь список `[0, len(nums))`, поэтому утверждение верно.
- Если `nums[mid] < target`, середина и всё слева слишком малы. Новый
  `lo = mid + 1` удаляет только невозможные индексы.
- Если `nums[mid] > target`, середина и всё справа слишком велики. Так как
  `hi` не входит в полуинтервал, новый `hi = mid` исключает `mid`.
- Если границы встретились, `[lo, hi)` пуст. Возможных индексов не осталось.

После каждой незавершившей итерации длина области `hi - lo` строго
уменьшается. Это не просто оценка скорости, а защита от вечного цикла.
Присваивание `lo = mid` при двух соседних элементах могло бы оставить ту же
область: середина округляется вниз и цикл перестаёт продвигаться.

### Реализация после инварианта

```python
def binary_search(nums: list[int], target: int) -> int:
    lo = 0
    hi = len(nums)

    while lo < hi:
        mid = (lo + hi) // 2

        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid

    return -1
```

### Мини-пример с сухим прогоном

**Вход:** `nums = [1, 3, 5, 7]`, `target = 2`

**Выход:** `-1`

1. `[lo, hi) = [0, 4)`, `mid = 2`, значение `5 > 2`. Новый `hi = 2`.
2. Область `[0, 2)`, `mid = 1`, значение `3 > 2`. Новый `hi = 1`.
3. Область `[0, 1)`, `mid = 0`, значение `1 < 2`. Новый `lo = 1`.
4. `lo == hi == 1`: область пуста, возвращаем `-1`.

Для `target = 5` первая середина сразу даёт индекс `2`.

Время — O(log n), потому что размер области на каждом шаге уменьшается
примерно вдвое. Итеративный вариант хранит только три индекса, поэтому
дополнительная память O(1).

---

## Почему «найти любое» часто недостаточно

В списке `[4, 6, 6, 6, 10]` обычный точный поиск может вернуть любой из
трёх индексов со значением `6`. Это корректно, если условие просит лишь факт
или любой индекс. Но для вставки, диапазона одинаковых значений или выбора
минимальной подходящей вместимости нужна первая позиция.

Левая граница ищет не равенство, а место, где впервые выполняется предикат
`nums[index] >= target`.

Инвариант удобно разбить на две части:

- все индексы меньше `lo` уже точно содержат значения меньше `target`;
- все индексы от `hi` и правее уже точно содержат значения не меньше
  `target`.

Между `lo` и `hi` остаётся неизвестная область. Если `nums[mid] < target`,
граница находится правее и `lo` становится `mid + 1`. Иначе `mid` остаётся
кандидатом на первую подходящую позицию, поэтому `hi` становится `mid`.
При равенстве нельзя возвращать сразу: левее может лежать ещё одно такое же
значение. Когда неизвестная область исчезает, `lo == hi` указывает на
границу между «слишком мало» и «уже подходит».

```python
def lower_bound(nums: list[int], target: int) -> int:
    lo = 0
    hi = len(nums)

    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid

    return lo
```

### Мини-пример `lower_bound`

**Вход:** вместимости `[4, 6, 6, 10]`, нужно не меньше `7` мест

**Выход:** индекс `3`, вместимость `10`

1. `[0, 4)`, `mid = 2`, значение `6 < 7` — граница правее,
   `lo = 3`.
2. `[3, 4)`, `mid = 3`, значение `10 >= 7` — это кандидат, но проверяем,
   нет ли более левого; `hi = 3`.
3. `lo == hi == 3`: первая подходящая позиция равна `3`.

Для цели `6` функция вернёт индекс `1`, то есть первую из двух шестёрок.
Для цели `11` она вернёт `4`, длину списка: подходящего элемента нет. Это
не ошибка индекса, а полезная позиция, куда `11` можно было бы вставить,
сохранив сортировку.

---

## Ловушки границ

### Смешать включённую и невключённую правую границу

Для `[lo, hi)` начальное `hi = len(nums)`, условие цикла `lo < hi`, а
исключение правой половины записывается `hi = mid`. Если выбрать схему
`[lo, hi]`, правила будут другими: `hi = len(nums) - 1`,
`while lo <= hi`, `hi = mid - 1`. Обе схемы возможны, но смешивать строки
из них нельзя.

### Не уменьшить область

При `lo = mid` середина может совпасть с `lo`. На входе из двух элементов
границы тогда не сдвинутся. После каждой ветки проверяйте на бумаге:
`hi - lo` стало меньше?

### Забыть про дубликаты

«Нашёл равное — вернул» решает только поиск любого совпадения. Слова
«первый», «последний», «минимальный подходящий» требуют поиска границы.

### Спрятать стоимость сортировки

Если данные не отсортированы, подготовка стоит O(n log n). Ради одного
поиска линейный проход O(n) дешевле и проще. Бинарный поиск окупается, когда
порядок уже задан или по подготовленному индексу выполняется много запросов.

---

## Когда выбирать бинарный поиск

Ищите не только слово «отсортирован». Нужен монотонный ответ: слева условие
ложно, а после некоторой границы истинно, либо наоборот. В массиве это может
быть `capacity >= guest_count`. В другой задаче бинарный поиск может идти
не по элементам, а по возможному ответу, если проверка «этого значения уже
достаточно?» меняется только один раз. В M2 достаточно уверенно владеть
точным поиском и левой границей.

Это не два указателя с концов. В задаче о паре оба края участвуют в одной
сумме и за шаг удаляется один кандидат. В бинарном поиске середина разделяет
монотонное пространство и удаляет половину.

## Применение в Harbor

- По отсортированному индексу вместимостей `lower_bound` находит минимальную
  вместимость, которой хватает для запроса.
- Это **не** то же самое, что первая подходящая комната в исходном каталоге.
  Сортировка меняет порядок, поэтому контракт функции нужно выбрать заранее.
- Для одного `allocate` линейный проход остаётся O(n) и обычно проще.
- Для множества запросов по почти неизменному каталогу можно один раз
  заплатить за сортировку, а затем выполнять поиски за O(log n).

## Мини-голос

> Бинарный поиск требует порядка и монотонного решения по сторонам границы.
> Я работаю в `[lo, hi)` и сохраняю возможный ответ внутри этого полуинтервала.
> Каждая ветка строго уменьшает область, поэтому цикл заканчивается.
> Точный поиск может вернуть любое совпадение, `lower_bound` — первое не меньшее.
> Если сортировку пришлось делать сейчас, её O(n log n) нельзя скрывать.
