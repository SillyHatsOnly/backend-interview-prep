# 05 · Бинарный поиск

**Мост:** в домашке M0.5 поиск в отсортированном списке уже был: линейный
проход, потом деление пополам. Здесь закрепляем инвариант границ. Ошибка
почти всегда не в идее «делить пополам», а в том, какой кусок ещё может
содержать ответ.

**Вопрос сюжета:** как выкидывать половину списка и не выкинуть сам ответ?

### С собесов

«Напишите бинарный поиск», «почему зациклилось?», «чем отличается от двух
указателей?». Индекс считают на бумаге на массиве из 4–5 чисел.

---

## Словарь

| Термин | English | На пальцах |
|--------|---------|------------|
| бинарный поиск | binary search | Пока в отрезке есть элементы, смотрим середину и отбрасываем половину |
| полуинтервал | half-open range | У нас удобно `[left, right)`: левый входит, правый — уже нет |
| инвариант | invariant | Пока цикл жив, ответ, если он есть, лежит строго внутри этих границ |

---

## Под капотом (модель)

Список обязан быть отсортирован по неубыванию. Иначе середина ничего не
говорит о левой и правой части.

Границы: `left = 0`, `right = len(nums)`. Ищем, пока `left < right`.
Середина `mid = (left + right) // 2` лежит внутри полуинтервала.

- `nums[mid] == target` — вернуть `mid`. Если одинаковых несколько, любой
  индекс годится, пока в условии не попросили самый левый.
- `nums[mid] > target` — ответ не может быть в `mid` и правее. Новый
  `right = mid`. Середину не включаем.
- `nums[mid] < target` — ответ не может быть в `mid` и левее. Новый
  `left = mid + 1`.

Когда `left == right`, полуинтервал пуст, ответа нет, вернуть `-1`.

Пустой список: `right` сразу 0, цикл не начинается.

Почему не `right = mid - 1` вперемешку с полуинтервалом `[left, right]`.
Схема границ одна на всю задачу. Смешали «правый включён» и «правый не
включён» — либо вечный цикл на двух элементах, либо дырка, куда провалился
ответ. Сухой прогон на `[1, 2]` и на одном элементе ловит это до тестов.

Это не два указателя с концов. Там оба края реагируют на сумму. Здесь один
отрезок, и середина выбрасывает половину целиком.

Память O(1), время O(log n) сравнений. Если список не отсортирован, поиск
не «почти бинарный»: сначала сортировка, и для одного запроса дешевле
линейный проход.

---

## Мини-прогон

`[1, 3, 5, 7]`, target 5.

- left 0, right 4, mid 2, `nums[2] == 5` → индекс 2.

Target 2:

- mid 2, значение 5 > 2 → right = 2
- left 0, right 2, mid 1, значение 3 > 2 → right = 1
- left 0, right 1, mid 0, значение 1 < 2 → left = 1
- left == right → `-1`
