## Задание 1. allocate по вместимости *(обязательно)*

`allocate(rooms: list[MeetingRoom], req: BookingRequest) -> MeetingRoom | None`

Вернуть **первую** комнату, у которой `capacity >= guest_count`. Если такой
нет — `None`. Время брони пока не учитываем.

Сначала примеры: пустой список комнат; одна подходящая не первая; никто не
влезает. Потом полный перебор, он здесь и есть решение. Оцените его. Напишите, почему
хеш по вместимости ломает слово «первая».

Тесты на эти три края.

---

## Задание 2. Пара в отсортированном списке *(обязательно)*

Дан отсортированный по неубыванию список целых и `k`. Вернуть индексы двух
**разных** элементов с суммой `k`, либо `None`.

Полный перебор — два цикла. Улучшение — два указателя с концов, без множества.
Отдельно одной фразой: чем это не бинарный поиск.

Края: пусто; один элемент; пара есть; пары нет; два одинаковых числа дают k.

---

## Задание 3. Окно *(обязательно)*

Дан список неотрицательных целых `nums` и лимит `limit`. Вернуть **длину**
самого длинного непрерывного куска, сумма которого не больше `limit`.

Полный перебор: для каждой левой границы заново суммировать вправо. Потом окно, оба
края только вперёд.

Края: пустой список; `limit == 0` и в списке есть нули; ни один элемент не
влезает в лимит (длина 0); весь список влезает.

---

## Задание 4. Пересечение двух броней *(обязательно)*

Две брони заданы парами минут `(start, end)`, `start < end`. Вернуть `True`,
если отрезки пересекаются. Встык (`end` одной равен `start` другой) — **не**
пересечение.

Примеры нарисуйте на прямой. Сложность проверки двух отрезков — константа.
Код без цикла по комнатам.

---

## Задание 5. Текст *(обязательно)*

8–12 предложений. Возьмите задание 1 и задание 2. Почему в одном честный
O(n) оставляют, а во втором от квадрата уходят. Что платите памятью или
требованием «список уже отсортирован».

## Задание 6. Сложное · позже

Все брони одного дня — список интервалов. Вернуть, хватит ли **одной**
комнаты (никакие два интервала не пересекаются). Сначала сортировка по
началу. Это мост к M3, не блокер закрытия M2.

---

## Задание 7. Новое · углубление · монотонный стек

`next_larger_capacity(capacities: list[int]) -> list[int | None]`

Для каждой комнаты вернуть вместимость первой комнаты **справа**, которая
строго больше. Если такой комнаты нет, на этой позиции вернуть `None`.

Пример:

```text
[4, 2, 5, 3] → [5, 5, None, None]
```

Сначала напишите полный перебор с двумя циклами и оцените его. Затем решите
за O(n) с монотонным стеком индексов. До кода сформулируйте инвариант: какие
комнаты лежат в стеке, почему они ещё не получили ответ и в каком порядке
идут их вместимости.

Края: пустой список; одна комната; строго убывающий ряд; одинаковые
вместимости не считаются большими; один новый элемент закрывает несколько
ожиданий.

## Задание 8. Новое · углубление · левая граница

`first_fit_index(sorted_capacities: list[int], guest_count: int) -> int | None`

Список вместимостей уже отсортирован по неубыванию. Вернуть индекс первого
значения, которое не меньше `guest_count`, или `None`, если такого значения
нет. Реализуйте бинарный поиск руками через полуинтервал `[lo, hi)`.

Примеры:

```text
[4, 6, 6, 10], 6  → 1
[4, 6, 6, 10], 7  → 3
[4, 6, 6, 10], 11 → None
```

Прогоните границы на каждом примере. В тексте отдельно объясните, почему эта
функция не заменяет задание 1: здесь ищется минимальная подходящая
вместимость в отсортированном ряду, а там — первая комната в исходном
порядке.

Края: пустой список; цель меньше первого элемента; несколько равных
значений; цель больше последнего.

---

## Задание 9. Новое · углубление · сломать окно

В задаче 3 числа были неотрицательными. Теперь разрешите отрицательные и
найдите конкретный вход, на котором алгоритм «расширить справа, а при
превышении лимита сразу сжимать слева» возвращает неверную максимальную
длину.

Сдать нужно не новый алгоритм, а разбор:

1. список, лимит и правильный ответ;
2. сухой прогон обычного окна до ошибочного ответа;
3. объяснение, какое монотонное свойство исчезло из-за отрицательных чисел;
4. вывод, почему нельзя чинить решение простой заменой `while` на `if`.

Это упражнение проверяет не знание следующего шаблона, а умение заметить,
что предпосылка текущего шаблона перестала выполняться.
