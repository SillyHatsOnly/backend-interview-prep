# 04 · Стек

**Мост:** в [главе об окне](./03_pointers_window.md) границы хранили один
активный непрерывный отрезок. Но у вложенных конструкций открытых элементов
может быть много, и закрывать их нужно в обратном порядке. Стек сохраняет
эту незавершённую историю. В следующей главе снова останутся всего две
границы — уже для бинарного поиска.

**Вопрос сюжета:** почему для вложенности достаточно смотреть только на
последний незавершённый элемент?

### С собесов

Частые вопросы: «Что такое стек?», «Как проверить скобки?», «Чем стек
отличается от очереди?», «Что хранится в стеке вызовов?». Сильный ответ
начинается не с `append`, а с порядка: тот, кто открылся последним, должен
закрыться первым.

---

## Словарь

- **Стек (stack)** — структура, в которой добавление и удаление происходят
  с одного конца.
- **Последним пришёл — первым ушёл (LIFO)** — правило порядка стека.
- **Вершина (top)** — последний добавленный элемент; только он доступен для
  следующего удаления.
- **Очередь (queue)** — другая структура: первым пришёл — первым ушёл.
- **Монотонный стек (monotonic stack)** — стек, элементы которого поддерживают
  возрастающий или убывающий порядок, пока ждут свой ответ.

В Python отдельный класс для обычного стека чаще всего не нужен. Список и
операции `append` и `pop()` с конца выражают его прямо.

---

## Под капотом: одна доступная вершина

```text
push("[")       push("(")       pop()          pop()

   ┌───┐           ┌───┐        ┌───┐
   │ [ │           │ ( │ ◄ top  │ [ │ ◄ top      пусто
   └───┘           ├───┤        └───┘
                   │ [ │
                   └───┘
```

Стек намеренно запрещает доставать элемент из середины. Это ограничение
полезно: если задача имеет тот же порядок завершения, вершина всегда и есть
единственный возможный следующий объект. Не нужно искать его среди всех
ранее открытых.

`list.append(value)` добавляет справа, а `list.pop()` снимает справа. Эти
операции работают за амортизированное O(1): иногда списку нужно увеличить
внутренний массив, но это не происходит при каждом добавлении. Снимать
первый элемент через `pop(0)` для стека не нужно и дорого: оставшиеся
элементы сдвигаются, поэтому операция стоит O(n).

### Когда выбирать стек

Стек подходит, если в условии слышен один из порядков:

- закрыть последнюю открытую конструкцию;
- отменить последнее выполненное действие;
- вернуться из последнего вызова;
- дождаться первого подходящего элемента справа, сохраняя незавершённые
  кандидаты.

Если нужен произвольный поиск по накопленным элементам, стек сам по себе не
поможет. Если обслуживать нужно того, кто пришёл раньше всех, нужна очередь,
а не стек.

## Мини-пример: правильная вложенность скобок

**Условие:** строка состоит из `()[]{}`. Вернуть `True`, если каждая
открывающая скобка закрывается парной скобкой в правильном порядке.

### Инвариант

После обработки любого префикса строки в стеке лежат все ещё не закрытые
скобки в порядке открытия, а вершина обязана закрыться следующей. Если
пришла закрывающая скобка и стек пуст, ей нечего закрывать. Если после всей
строки стек не пуст, часть конструкций так и осталась открытой.

```python
def is_balanced(text: str) -> bool:
    opening_for = {
        ")": "(",
        "]": "[",
        "}": "{",
    }
    stack: list[str] = []

    for char in text:
        if char in "([{":
            stack.append(char)
            continue

        if not stack or stack[-1] != opening_for[char]:
            return False
        stack.pop()

    return not stack
```

**Вход:** `([{}])`

**Выход:** `True`

**Сухой прогон:**

1. `(` — положили: стек `['(']`.
2. `[` — положили: стек `['(', '[']`.
3. `{` — положили: стек `['(', '[', '{']`.
4. `}` — вершина `{`, пара совпала; сняли `{`.
5. `]` — вершина `[`, сняли `[`.
6. `)` — вершина `(`, сняли `(`.
7. Строка закончилась, стек пуст: все открытия получили закрытие.

Для входа `([)]` количество круглых и квадратных скобок одинаково, но ответ
`False`. На символе `)` вершина равна `[`, а значит конструкции пересеклись:
закрывается не последняя открытая. Простой подсчёт количества такую ошибку
не видит.

Каждый символ добавляется и снимается не более одного раза: время O(n).
Память равна максимальной глубине вложенности; в худшем случае строка
состоит только из открывающих скобок, поэтому это O(n).

### Частые ошибки

1. Сравнить только количество открывающих и закрывающих скобок. Это не
   проверяет порядок вложения.
2. Вызвать `pop()` до проверки пустого стека и получить исключение на строке
   `")"`.
3. Вернуть `True` сразу после цикла, не проверив остаток. Строка `"((("`
   тогда ошибочно станет правильной.
4. Использовать очередь: первая открытая скобка не обязана закрываться
   первой.

## Стек и очередь — разные обещания

```text
СТЕК                         ОЧЕРЕДЬ
добавить → [A, B, C]         добавить → [A, B, C] → забрать
                 ↑                       ↑
              забрать                 первым A
              первым C
```

Стек нужен для вложенности и отката: `C` завершится раньше `B`, а `B` —
раньше `A`. Очередь нужна для порядка поступления: сначала обслужить `A`,
затем `B`, затем `C`. В M3 очередь появится в обходе графа в ширину; менять
одну структуру на другую без смены смысла нельзя.

## Лёгкая монотонная идея

Пусть комнаты стоят вдоль коридора, а для каждой нужно найти первую комнату
справа с **большей** вместимостью.

**Вход:** `[4, 2, 5, 3]`

**Выход:** `[5, 5, None, None]`

Стек хранит индексы комнат, которые ещё ждут большую вместимость. Их
вместимости идут сверху вниз так, чтобы новый больший элемент мог закрыть
сразу несколько ожиданий.

1. Видим `4`: ответа справа пока нет, кладём индекс `0`.
2. Видим `2`: `2` не больше `4`, кладём индекс `1`. В стеке вместимости
   `[4, 2]`.
3. Видим `5`: он больше вершины `2`, значит ответ для индекса `1` — `5`.
   Снимаем `1`. Он также больше `4`, значит ответ для индекса `0` — `5`.
   Снимаем `0`, затем кладём индекс `2`.
4. Видим `3`: он не больше `5`, кладём индекс `3`.
5. В конце индексы `2` и `3` остались без большей комнаты справа.

Каждый индекс кладут один раз и снимают не более одного раза, поэтому
суммарное время O(n), хотя внутри прохода есть `while`. На этом этапе важно
не заучивать шаблон, а увидеть модель: стек хранит **неразрешённые**
кандидаты, а новый элемент разрешает ожидания с вершины.

## Применение в Harbor

- История отмены хранит последние действия: сначала отменяется самое свежее.
- Вложенные правила расписания или разбор выражения закрываются в обратном
  порядке открытия.
- Явный стек может заменить глубокую рекурсию, если нужно самостоятельно
  управлять незавершёнными шагами обхода.
- Монотонный стек помогает отвечать на вопросы «первый больший справа» для
  ряда вместимостей или времён ожидания.

## Мини-голос

> Стек хранит незавершённые элементы в порядке LIFO.
> В задаче о скобках вершина — единственное открытие, которое можно закрыть сейчас.
> Добавление и снятие с конца списка амортизированно стоят O(1).
> Очередь обслуживает первого, стек — последнего; это разные контракты.
> Монотонный стек держит кандидатов, которые ещё ждут свой ответ.
