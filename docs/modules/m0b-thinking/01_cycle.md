# 01 · Цикл решения задачи

**Мост:** после M0 у вас есть привычка учить блоками. Здесь — привычка
**разбирать** задачу, чтобы в M1–M3 код не обгонял мысль.

**Вопрос сюжета:** что делать в первую минуту, когда условие ещё не «кликнуло»?

### С собесов

Типичный провал: сразу писать код или молчать. Ждут уточнений, примеров,
brute force, оценки, потом улучшение. Медленный связный голос лучше тишины.

---

## Словарь

| Термин | English | На пальцах |
|--------|---------|------------|
| условие | problem statement | Что дано и что вернуть |
| край / крайний случай | edge case | Пустой вход, один элемент, дубликаты, огромный n |
| полный перебор | brute force | Самое простое верное, часто медленное |
| сложность | complexity / Big O | Порядок роста времени/памяти от размера входа |
| паттерн задачи | algorithmic pattern | Узнаваемая схема (два указателя, окно, BFS…) |
| инвариант | invariant | Что остаётся верным на каждом шаге алгоритма |

---

## Цикл (запомните порядок)

1. **Уточнить.** Что на входе/выходе? Ограничения? Что при пустом входе?
   Перескажите условие своими словами.
2. **Свои примеры.** 2–3 пары «вход → выход», включая край. Если не можете
   придумать пример — условие ещё не понято.
3. **Brute force.** Самое тупое верное решение вслух. Зафиксируйте, что оно
   правильно, даже если медленное.
4. **Оценить.** Грубая сложность brute. Где узкое место (что перебираем зря)?
5. **Упростить / узнать.** Можно ли отсортировать? Хеш? Два указателя?
   Свести к уже решённой задаче? (В M2–M3 появится словарь паттернов —
   здесь важнее сам вопрос «что упрощает».)
6. **Код.** Писать только после шагов 1–5 (на бумаге/вслух можно псевдокод).
7. **Edges + рефлексия.** Прогнать края. Одна фраза: «в следующий раз я
   сразу проверю …».

На собесе шаги 1–5 — это и есть половина оценки. Код без них — риск.

---

## Под капотом (модель)

Голова держит не «магический паттерн», а **карту задачи**:

- пространство входа (какие формы данных бывают);
- цель (что минимизировать/найти);
- ограничения (время, память, онлайн/офлайн).

Brute force заполняет карту. Улучшение — сжатие перебора за счёт структуры
(порядок, хеш, инвариант окна). Пока карты нет, паттерн не к чему приклеить.

## Мини-пример вслух

**Задача:** в списке целых найти два числа с суммой `target` (или сказать,
что пары нет).

1. Уточнить: порядок важен? Дубликаты? Один элемент дважды?
2. Пример: `[2, 7, 11], 9` → `(2, 7)`; `[]` → нет; `[3], 3` → нет.
3. Brute: два вложенных цикла, O(n²).
4. Узкое место: для каждого i ищем пару слепым проходом.
5. Упростить: хеш уже виденных чисел → O(n) среднее.
6. Код (после рассуждения).
7. Края: отрицательные, два одинаковых, пустой список.

Не копируйте этот ответ на все задачи — копируйте **порядок шагов**.

---

## До / после

**Плохо:** «Это же two sum, хеш» → код → падение на крае.

**Хорошо:** условие → примеры → brute → «хеш убирает второй цикл» → код → края.

---

## Применение

- Каждая easy на работе / дома — через цикл, даже за 10 минут.
- Harbor `allocate` позже: сначала примеры комнат и запроса, потом brute
  «пройти список», потом структура.
- Мок алго: первую треть времени — только голос цикла.

## Мини-голос

> Сначала условие и свои примеры, потом brute и оценка, потом улучшение и код.
> Тишина хуже медленного рассуждения. Паттерн — после карты задачи, не вместо.
