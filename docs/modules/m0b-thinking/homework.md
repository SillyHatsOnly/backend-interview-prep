## Задание 1 *(обязательно)*

Дан список целых `nums` и число `k`. Вернуть `True`, если есть два **разных
индекса** i, j с `nums[i] + nums[j] == k`.

Пройдите цикл полностью. Сначала brute, потом лучше, если получится.

??? warning "Разбор · задание 1 · не открывать до своей попытки"

    **Уточнить.** Вход: список целых и число `k`. Выход: bool. Нужны разные
    индексы (одно и то же число дважды в списке — ок, если это две позиции).
    Пустой список / один элемент → `False`.

    **Примеры.** `[10, 15, 3, 7]`, k=`17` → True; `[1, 2, 3, 4]`, k=`8` → False;
    `[5, 1, 5]`, k=`10` → True; `[]` → False.

    **Brute.** Два вложенных цикла по индексам i < j, проверка суммы. Time O(n²),
    extra O(1).

    **Узкое место.** Повторно спрашиваем «видели ли уже дополнение до k».

    **Улучшение.** Один проход + множество уже встреченных значений: для `x`
    проверяем `k - x in seen`, затем кладём `x` в `seen`. Time O(n) average,
    extra O(n).

    **Рефлексия.** Сразу уточнять «разные индексы» и край с двумя одинаковыми
    числами, дающими в сумме `k`.

    ```python
    def check_sum(nums: list, k: int) -> bool:
        if len(nums) < 2:
            return False
        visited = set()
        for x in nums:
            target = k - x
            if target in visited:
                return True
            visited.add(x)
        return False


    import pytest

    @pytest.mark.parametrize(
        "nums, k, expected",
        [
            ([10, 15, 3, 7], 17, True),
            ([1, 2, 3, 4], 8, False),
            ([], 5, False),
            ([1], 4, False),
            ([5, 1, 5], 10, True),
            ([2, 4, 6], 4, False),
            ([-1, -3, 5, 8], 4, True),
            ([-5, -2, -3], -7, True),
        ],
    )
    def test_check_sum(nums: list, k: int, expected: bool) -> None:
        assert check_sum(nums, k) == expected
    ```

## Задание 2 *(обязательно)*

Дана строка из скобок `()[]{}`. Вернуть, правильная ли последовательность.

Цикл: примеры с ошибками (`(]`, `([)]`, пустая строка). Brute можно описать
как «перебор всех раскладок» — затем стек как улучшение (если догадались;
если нет — честно оставьте brute и напишите, где застряли).

??? warning "Разбор · задание 2 · не открывать до своей попытки"

    **Уточнить.** Только три вида скобок. Пустая строка — валидна. Нечётная
    длина — сразу нет. Перекрытие разных типов (`([)]`) — нет.

    **Примеры.** `()[]{}` → True; `{[()]}` → True; `([)]` → False; `(` → False;
    `)(` → False.

    **Brute.** Перебор всех способов «спаривания» / наивные замены `()` `[]` `{}`
    подряд — медленно и хрупко. Time хуже, чем линейный стек.

    **Улучшение.** Стек: открывающая → push; закрывающая → top должен быть парой,
    иначе False; в конце стек пуст. Time O(n), extra O(n).

    **Рефлексия.** Сразу стек + таблица пар; отдельно проверить пересечение типов.

    ```python
    def is_valid_brackets(s: str) -> bool:
        if not s:
            return True
        if len(s) % 2 != 0:
            return False
        stack = []
        mapping = {")": "(", "]": "[", "}": "{"}
        for char in s:
            if char in mapping:
                if not stack or stack[-1] != mapping[char]:
                    return False
                stack.pop()
            else:
                stack.append(char)
        return len(stack) == 0


    import pytest

    @pytest.mark.parametrize(
        "s, expected",
        [
            ("()[]{}", True),
            ("{[()]}", True),
            ("([)]", False),
            ("", True),
            ("(", False),
            ("(()", False),
            ("(((", False),
            ("))", False),
            (")(", False),
        ],
    )
    def test_is_valid_brackets(s: str, expected: bool) -> None:
        assert is_valid_brackets(s) == expected
    ```

## Задание 3 *(обязательно)*

Дан отсортированный по неубыванию список целых и `target`. Вернуть индекс
`target` или `-1`.

Цикл обязателен. Линейный поиск — brute; бинарный — улучшение. Если бинарный
ещё не уверенно — сдайте линейный + честную оценку и вопрос «как сузить
поиск вдвое».

??? warning "Разбор · задание 3 · не открывать до своей попытки"

    **Уточнить.** Список уже отсортирован по неубыванию; целые, в т.ч.
    отрицательные; пустой → `-1`. Нужен любой индекс вхождения (не обязательно
    первый).

    **Примеры.** `[1, 2, 3, 4]`, target `2` → `1`; `[]` → `-1`; `[1]` → `0`;
    `[-3, 1, 2, 4]`, target `-3` → `0`.

    **Brute.** Линейный проход. Time O(n), extra O(1). Узкое место: сортировка
    не используется.

    **Улучшение.** Бинарный поиск, полуинтервал `[left, right)`:
    `left = 0`, `right = len(nums)`, пока `left < right`,
    `mid = (left + right) // 2`. Равно → вернуть mid; `nums[mid] > target` →
    `right = mid`; иначе `left = mid + 1`. Не нашли → `-1`. Time O(log n),
    extra O(1).

    **Типичная ошибка.** Перевёрнутые ветки; псевдокод на бумаге разъехался с
    кодом (например `right = mid + 1` при полуинтервале). Сверять пальцем тем
    же инвариантом, что в файле. Не путать с двумя указателями.

    **Рефлексия.** Сразу спросить, отсортирован ли вход; если да — бинпоиск.

    ```python
    def bin_search(nums: list, target: int) -> int:
        if not nums:
            return -1
        left_border, right_border = 0, len(nums)
        while left_border < right_border:
            middle_position = (left_border + right_border) // 2
            if nums[middle_position] == target:
                return middle_position
            elif nums[middle_position] > target:
                right_border = middle_position
            else:
                left_border = middle_position + 1
        return -1


    import pytest

    @pytest.mark.parametrize(
        "nums, target, expected",
        [
            ([1, 2, 3, 4, 5], 5, 4),
            ([], 1, -1),
            ([1], 1, 0),
            ([-1], -1, 0),
            ([1, 2], 1, 0),
            ([-4, -3, -2, -1, 0], -3, 1),
            (None, 1, -1),
            ([0, 1, 2, 4, 6], 0, 0),
        ],
    )
    def test_bin_search(nums, target, expected):
        assert bin_search(nums, target) == expected
    ```

    `None` здесь молча даёт `-1` через `if not nums` — на собесе лучше уточнить.

## Задание 4 · текст *(обязательно)*

8–12 предложений: почему на собесе полезнее сказать brute force вслух, чем
молчать в ожидании O(n). Один пример из заданий 1–3.

??? warning "Разбор · задание 4 · не открывать до своей попытки"

    Полезно проговорить brute force вслух: так виден цикл решения. Интервьюер
    видит, что есть план — сначала простое верное решение «в лоб», чтобы задача
    вообще выполнялась. Дальше его оценивают, смотрят оптимальность и решают,
    улучшать или оставить.

    Так появляется система, а не хаос «сразу угадать O(n)». Даже у опытных есть
    порядок работы; поступательный путь снижает риск пропустить края и важное
    уточнение. Молчание в ожидании идеальной сложности выглядит как ступор;
    озвученный O(n)-план — уже прогресс и материал для диалога.

    Пример — задание 3. Сначала полный проход по списку: target есть или нет,
    сложность O(n) в худшем случае. Затем идея сузить поиск вдвое на
    отсортированном входе — бинарный поиск O(log n). Псевдокод, прогон пальцем
    по границам, код и тесты на края; расхождения псевдокода с кодом ловятся
    тестами и правятся. Итог — верное решение эффективнее первого brute.

## Задание 5 · Harbor и разбор чужого кода *(обязательно)*

Контракт: дан каталог комнат `(room_id, capacity)` и положительное число
гостей. Вернуть id подходящей комнаты с **наименьшим лишним запасом мест**.
Если вместимость одинакова, сохранить порядок исходного каталога. Если
подходящей комнаты нет, вернуть `None`.

Коллега прислал такой вариант:

```python
def choose_room(
    rooms: list[tuple[str, int]],
    guests: int,
) -> str | None:
    rooms.sort(key=lambda room: room[1])
    for room_id, capacity in rooms:
        if capacity >= guests:
            return room_id
    return None
```

Сначала сделайте ревью, не переписывая функцию:

1. Прогоните её на `[("A", 8), ("B", 4), ("C", 6)]`, `guests=5`. Ожидаемый
   ответ — `"C"`.
2. Назовите не меньше двух свойств, которые код меняет или тратит без
   необходимости. Подсказка: что стало с исходным списком и сколько стоит
   полная сортировка?
3. Уточните контракт для `guests <= 0`, пустого каталога и двух комнат одной
   вместимости. Зафиксируйте выбранное поведение в тестах.
4. Перепишите решение одним проходом без мутации входа. Сформулируйте
   инвариант: после обработанного префикса `best` хранит лучшую подходящую
   комнату этого префикса или отсутствует.
5. Сдайте полный цикл, код, тесты, время и дополнительную память.

Здесь O(n) — достаточно хорошее решение: каждую комнату всё равно надо
проверить, а сортировка O(n log n) создаёт порядок, который функция целиком
не использует.

??? warning "Разбор · задание 5 · не открывать до своей попытки"

    **Ревью коллеги.** На `[("A", 8), ("B", 4), ("C", 6)]`, `guests=5` после
    `sort` порядок становится `[B4, C6, A8]`, функция возвращает `"C"` —
    ответ совпал с контрактом. Но код **мутирует** вход (`rooms.sort`) и
    платит O(n log n) по времени плюс доп. память Timsort. Контракт — не
    «первая подходящая в исходном списке» (это было бы `"A"`), а комната с
    **минимальной** подходящей вместимостью; при равенстве — первая в
    *исходном* порядке. Stable sort часто сохраняет ничью, поэтому баг по
    ничьей маскируется; мутация и цена — нет. Для `guests <= 0` и пустого
    каталога фиксируем `None` в тестах (положительное число гостей в условии).

    **Инвариант одного прохода.** После префикса списка `best_id` /
    `best_capacity` — лучшая подходящая комната этого префикса или ещё нет
    кандидата. Нового кандидата берём только при `capacity >= guests` и
    **строго** `capacity < best_capacity` (равенство не трогаем — сохраняем
    более ранний id).

    **Сложность:** O(n) время, O(1) доп. память. Сортировка не нужна.

    ```python
    def choose_room(
        rooms: list[tuple[str, int]],
        guests: int,
    ) -> str | None:
        if not rooms or guests < 1:
            return None
        best_id: str | None = None
        best_capacity = float("inf")
        for room_id, capacity in rooms:
            if capacity >= guests and capacity < best_capacity:
                best_capacity = capacity
                best_id = room_id
        return best_id
    ```

    ```python
    import pytest

    @pytest.mark.parametrize(
        "rooms, guests, expected",
        [
            ([("A", 8), ("B", 4), ("C", 6)], 5, "C"),
            ([("A", 8), ("B", 4), ("C", 4)], 3, "B"),
            ([("A", 8), ("B", 4), ("C", 4)], 4, "B"),
            ([("A", 8), ("B", 4), ("C", 4)], 7, "A"),
            ([("A", 8), ("B", 4), ("C", 4)], 9, None),
            ([("A", 8), ("B", 4), ("C", 6)], 0, None),
            ([], 4, None),
        ],
    )
    def test_choose_room(rooms, guests, expected):
        assert choose_room(rooms, guests) == expected
        # каталог не должен мутировать
        assert rooms == list(rooms)
    ```

    Типичные провалы на ревью: вернуть список всех «лучших»; взять первую
    подходящую без минимума запаса; оставить `.sort`; опечатки в тестах
    (`gusets`, `5 -> 'C'` вместо `, 5, "C"`).
