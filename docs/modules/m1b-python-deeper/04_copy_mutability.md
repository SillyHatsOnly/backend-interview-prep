# 04 · Ссылки, копии и мутация

**Мост:** в [03](./03_args_comprehensions.md) мы строили новые списки и
словари из каталога. Новая внешняя коллекция ещё не означает новые объекты
внутри неё. Здесь нарисуем ссылки и выберем, где Harbor нужен общий объект,
где поверхностная копия, а где настоящий снимок. В следующей главе эта
граница владения поможет разнести модели и операции по модулям.

**Вопрос сюжета:** почему изменение тега в «копии» каталога может изменить
оригинал и как спроектировать данные так, чтобы этого не произошло?

### С собесов и из продакшена

Классические вопросы: «что делает присваивание», «чем shallow copy
отличается от deep copy», «почему опасен изменяемый default». В рабочем коде
ошибка проявляется позже: функция получила список «только почитать»,
добавила элемент, а кэш или объект вызывающего кода поменялся вместе с ним.
Чтобы предсказать это, нужно думать не коробками со значениями, а графом
объектов и ссылок.

---

## Словарь

| Термин | English | На пальцах |
|--------|---------|------------|
| объект | object | Значение, которое живёт в памяти: список, строка, комната |
| имя / ссылка | name / reference | Способ добраться до объекта; несколько имён могут вести к одному месту |
| изменяемый объект | mutable object | Его содержимое можно поменять на месте: `list`, `dict`, `set` |
| неизменяемый объект | immutable object | Его значение на месте не меняется: `int`, `str`, обычный `tuple` |
| псевдоним | alias | Второе имя или путь к тому же объекту |
| поверхностная копия | shallow copy | Новый внешний контейнер, но вложенные объекты остаются общими |
| глубокая копия | deep copy | Рекурсивно создаёт копии достижимых вложенных объектов |
| владение | ownership | Договор о том, кто имеет право менять объект и кто увидит изменение |
| защитная копия | defensive copy | Копия на границе, чтобы внешний код не менял внутреннее состояние напрямую |

В Python переменная не является коробкой, в которую целиком помещён список.
Имя указывает на объект. Присваивание обычно меняет стрелку от имени, а не
дублирует сам объект.

---

## Модель: имя указывает на объект

```python
original = ["quiet"]
alias = original

alias.append("projector")

assert original == ["quiet", "projector"]
assert alias is original
```

После `alias = original` существуют два имени, но один список:

```text
original ─┐
          ├────> list #1 ["quiet"]
alias ────┘
```

`append` меняет `list #1` на месте, поэтому новое содержимое видно через
оба имени. Оператор `is` проверяет идентичность — ведут ли ссылки к одному
объекту. Оператор `==` проверяет равенство значений. Два разных списка могут
быть равны:

```python
left = ["quiet"]
right = ["quiet"]

assert left == right
assert left is not right
```

Для доменной логики почти всегда важно `==`. `is` обычно используют для
одиночных специальных объектов, прежде всего `value is None`, а в этой
главе — чтобы исследовать граф ссылок.

---

## Передача в функцию: передаётся та же ссылка

```python
def add_projector(tags: list[str]) -> None:
    tags.append("projector")


room_tags = ["quiet"]
add_projector(room_tags)
assert room_tags == ["quiet", "projector"]
```

Параметр `tags` становится ещё одним именем того же списка. Функция не
получает автоматическую копию.

Но переназначение локального имени не меняет стрелку вызывающего кода:

```python
def replace_tags(tags: list[str]) -> None:
    tags = ["whiteboard"]


room_tags = ["quiet"]
replace_tags(room_tags)
assert room_tags == ["quiet"]
```

Внутри `replace_tags` имя `tags` сначала смотрело на исходный список, затем
его перенаправили на новый. Сам исходный объект не мутировал. Разница между
`tags.append(...)` и `tags = ...` — это разница между изменением объекта и
переназначением ссылки.

---

## Поверхностная копия

Список можно поверхностно скопировать несколькими равноправными способами:

```python
copy_a = original.copy()
copy_b = list(original)
copy_c = original[:]
```

Для словаря есть `mapping.copy()` и `dict(mapping)`. Все они создают новый
**внешний** контейнер. Если элементы сами изменяемы, стрелки внутри копии
ведут к прежним объектам.

```python
catalog = {
    "A": {"tags": ["quiet"]},
}
snapshot = catalog.copy()

snapshot["A"]["tags"].append("projector")

assert catalog["A"]["tags"] == ["quiet", "projector"]
assert snapshot is not catalog
assert snapshot["A"] is catalog["A"]
```

Схема:

```text
catalog  ──> dict #1 ── "A" ─┐
                              ├──> dict room #3 ── "tags" ──> list #4
snapshot ──> dict #2 ── "A" ─┘
```

Новый `dict #2` позволяет независимо добавить или удалить ключ верхнего
уровня. Но значение по ключу `"A"` общее, поэтому изменение вложенных тегов
видно с обеих сторон. Поверхностная копия не «сломана» — она выполнила
точный договор. Ошибка появляется, если мы ожидали от неё глубокий снимок.

---

## Глубокая копия

`copy.deepcopy` обходит граф достижимых объектов и старается скопировать
каждый изменяемый узел:

```python
from copy import deepcopy


catalog = {
    "A": {"tags": ["quiet"]},
}
snapshot = deepcopy(catalog)

snapshot["A"]["tags"].append("projector")

assert catalog["A"]["tags"] == ["quiet"]
assert snapshot["A"]["tags"] == ["quiet", "projector"]
```

```text
catalog  ──> dict #1 ──> room dict #3 ──> tags list #5

snapshot ──> dict #2 ──> room dict #4 ──> tags list #6
```

Глубокая копия помнит уже скопированные объекты, поэтому умеет сохранять
общие ссылки внутри графа и обрабатывать многие циклические структуры. Но
это техническая возможность, а не автоматический правильный смысл.

Почему не стоит ставить `deepcopy` на каждую границу:

- большой граф копируется целиком и расходует время и память;
- соединение с БД, файл, блокировка или внешний клиент не становятся
  осмысленно «вторыми» ресурсами;
- объект может опираться на идентичность: две копии одной сущности уже не
  должны считаться независимыми сущностями;
- глубокая копия сохраняет текущие данные, включая уже нарушенный инвариант;
  она не выполняет бизнес-валидацию.

Сначала определите владение и форму снимка. `deepcopy` берите, только если
действительно нужен независимый граф и все его узлы имеют понятную семантику
копирования.

## Dataclass: три знакомые ловушки

### 1. Изменяемое значение по умолчанию

В M1 мы уже видели правило:

```python
from dataclasses import dataclass, field


@dataclass
class RoomDraft:
    id: str
    tags: list[str] = field(default_factory=list)
```

`default_factory=list` создаёт отдельный список для каждого экземпляра.
Она решает проблему общего default, но не делает список неизменяемым и не
копирует значение, явно переданное снаружи:

```python
external = ["quiet"]
draft = RoomDraft("A", external)

external.append("projector")
assert draft.tags == ["quiet", "projector"]
```

Если класс должен владеть независимым списком, это нужно выразить на
границе, например фабрикой, которая принимает `Iterable[str]` и строит
`list(tags)`. Если теги по смыслу являются снимком, проще хранить кортеж.

### 2. `frozen=True` замораживает поля, но не граф

```python
@dataclass(frozen=True)
class FrozenOutside:
    id: str
    tags: list[str]


room = FrozenOutside("A", ["quiet"])
# room.tags = []              # FrozenInstanceError
room.tags.append("projector") # допустимо: мутирует list, а не поле room.tags
```

`frozen` перехватывает попытку присвоить атрибут. Вызов метода вложенного
списка проходит напрямую к списку. Поэтому для снимка комнаты подходит:

```python
@dataclass(frozen=True, slots=True)
class MeetingRoom:
    id: str
    capacity: int
    tags: tuple[str, ...] = ()
```

Кортеж нельзя дописать на месте. Однако и это не магическая «глубокая
заморозка»: кортеж может содержать изменяемый объект. Здесь аннотация
`tuple[str, ...]` важна ещё и по смыслу — строки неизменяемы.

### 3. `dataclasses.replace` копирует поля поверхностно

```python
from dataclasses import replace


draft = RoomDraft("A", ["quiet"])
renamed = replace(draft, id="A-101")

assert renamed is not draft
assert renamed.tags is draft.tags
```

`replace` вызывает конструктор с прежними значениями полей и указанными
заменами. Внешний dataclass новый, но список `tags` передан той же ссылкой.
Если нужен независимый список, задайте это явно:

```python
renamed = replace(draft, id="A-101", tags=draft.tags.copy())
```

## Проектируем Harbor через владение

Хорошая модель не требует угадывать, кто может менять данные:

```python
@dataclass(frozen=True, slots=True)
class Booking:
    request_id: str
    room_id: str


@dataclass(frozen=True, slots=True)
class MeetingRoom:
    id: str
    capacity: int
    tags: tuple[str, ...] = ()


Schedule = dict[str, list[Booking]]
```

Описание комнаты и отдельная бронь — неизменяемые факты. Расписание —
изменяемое состояние хранилища. Такой разрез лучше, чем замороженная комната
с вложенным изменяемым списком броней: по типам видно, где ожидается мутация.

Если отчёту нужен снимок расписания, можно намеренно заменить изменяемые
списки кортежами:

```python
ScheduleSnapshot = dict[str, tuple[Booking, ...]]


def snapshot_schedule(schedule: Schedule) -> ScheduleSnapshot:
    return {
        room_id: tuple(bookings)
        for room_id, bookings in schedule.items()
    }
```

Новый словарь отделяет верхний уровень, кортежи — коллекции броней, а сами
`Booking` безопасно разделяются, потому что они `frozen` и состоят из строк.
Мы не копируем всё вслепую: строим ровно ту неизменяемую форму, которая нужна
отчёту.

## Сухой прогон: alias, shallow, deep

```python
from copy import copy, deepcopy


draft = RoomDraft("A", ["quiet"])
alias = draft
shallow = copy(draft)
deep = deepcopy(draft)

shallow.tags.append("projector")
deep.tags.append("window")
```

1. `alias = draft`: новый объект не создаётся; оба имени ведут к одному
   `RoomDraft`.
2. `copy(draft)`: создаётся второй `RoomDraft`, но его `tags` указывает на
   исходный список.
3. `deepcopy(draft)`: создаётся третий `RoomDraft` и отдельный список тегов.
4. `shallow.tags.append("projector")` меняет общий список, видимый через
   `draft`, `alias` и `shallow`.
5. `deep.tags.append("window")` меняет только глубокую копию.

**Итог:**

```python
assert draft.tags == ["quiet", "projector"]
assert alias.tags == ["quiet", "projector"]
assert shallow.tags == ["quiet", "projector"]
assert deep.tags == ["quiet", "window"]

assert alias is draft
assert shallow is not draft
assert shallow.tags is draft.tags
assert deep.tags is not draft.tags
```

## Применение в Harbor

- `MeetingRoom` хранит теги как `tuple[str, ...]`, если это снимок
  справочника.
- Изменяемое расписание отделено от описания комнаты.
- Функция, обещающая «только чтение», не мутирует полученный список тайно.
- Снимок строится в явную форму `dict[str, tuple[Booking, ...]]`, а не
  бездумным `deepcopy` всего приложения.
- `dataclasses.replace` считается поверхностной операцией, пока явно не
  скопированы нужные поля.

## Мини-голос

> Присваивание создаёт ещё одну ссылку, а не копию объекта. Поверхностная
> копия создаёт новый внешний контейнер, но делит вложенные объекты.
> `deepcopy` рекурсивен, однако не знает бизнес-смысла и не чинит инварианты.
> `frozen` запрещает присвоить поле, но не замораживает вложенный список.
> Я сначала определяю владельца данных, затем выбираю общую ссылку, копию
> или неизменяемый снимок.
