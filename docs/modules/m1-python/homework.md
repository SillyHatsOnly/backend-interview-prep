## Задание 1. Dataclass *(обязательно)*

В `harbor-capstone` (заведёте сами в M0):

1. `@dataclass(frozen=True)` модель `MeetingRoom`: `id: str`, `capacity: int`,
   `tags: tuple[str, ...] = ()`.
2. `@dataclass` (не frozen) `BookingRequest`: `guest_count: int`,
   `duration_minutes: int`. В `__post_init__`: оба > 0, иначе `ValueError`.
3. Тесты: создание; `MeetingRoom` нельзя менять; невалидный запрос падает.
4. **`pyright`** — когда подключите руками; до этого достаточно тестов.

??? warning "Разбор · задание 1 · не открывать до своей попытки"

    Комната — снимок: после создания поля не меняются, поэтому `frozen=True`.
    Идентификатор — строка (`"A101"`), не число. Теги — кортеж любой длины:
    аннотация `tuple[str, ...]`, не `tuple[str]` (та означает ровно одну строку).

    Запрос на бронь менять можно, но нулевые гости или нулевая длительность
    бессмысленны. `__post_init__` проверяет это сразу после создания и бросает
    `ValueError`. Проверка идёт по очереди: если оба поля плохие, сообщение
    будет про гостей — это нормально, если тест на это согласен.

    ```python
    from dataclasses import dataclass


    @dataclass(frozen=True)
    class MeetingRoom:
        id: str
        capacity: int
        tags: tuple[str, ...] = ()


    @dataclass
    class BookingRequest:
        guest_count: int
        duration_minutes: int

        def __post_init__(self) -> None:
            if self.guest_count <= 0:
                raise ValueError("Количество гостей не может быть меньше или равно 0!")
            if self.duration_minutes <= 0:
                raise ValueError("Количество минут не может быть меньше или равно 0!")
    ```

    В тестах экземпляр называйте `room` / `request`. Имя `cls` в этой главе
    занято: так называют класс внутри `@classmethod`.

## Задание 2. classmethod *(обязательно)*

У `MeetingRoom` метод `from_mapping(cls, data: dict) -> MeetingRoom`:
ключи `"id"`, `"capacity"`, опционально `"tags"` (list → tuple).  
Тест round-trip: dict → объект → поля совпали.

??? warning "Разбор · задание 2 · не открывать до своей попытки"

    Фабрика собирает объект того класса, у которого её вызвали: `return cls(...)`,
    не `MeetingRoom(...)`. Поля передавайте по имени. Позиционный вызов
    сломается, если порядок полей в классе изменится.

    Список тегов из словаря сам в кортеж не превращается. Пустой список и
    отсутствующий ключ — оба «тегов нет». Непустой список нужно явно обернуть
    в `tuple`, иначе внутри замороженной комнаты останется изменяемый `list`.

    ```python
    @classmethod
    def from_mapping(cls, data: dict) -> "MeetingRoom":
        return cls(
            id=data["id"],
            capacity=data["capacity"],
            tags=tuple(data.get("tags") or []),
        )
    ```

    В тесте нужен и уже готовый кортеж, и список: `'tags': ['projector']`
    должен стать `('projector',)`.

## Задание 3. Декоратор *(обязательно)*

`@count_calls` — считает вызовы (`wrapper.call_count`), с `functools.wraps`.  
Тест: три вызова → `call_count == 3`, `__name__` сохранено.

??? warning "Разбор · задание 3 · не открывать до своей попытки"

    Обёртка увеличивает свой же счётчик и вызывает исходную функцию.
    Счётчик вешают на `wrapper` до `return`, иначе первый вызов не найдёт
    атрибут. `@wraps(func)` копирует имя и докстринг, иначе снаружи функция
    будет называться `wrapper`.

    ```python
    from functools import wraps


    def count_calls(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            wrapper.call_count += 1
            return func(*args, **kwargs)

        wrapper.call_count = 0
        return wrapper
    ```

    Тест: до вызовов `call_count == 0`, после трёх — `3`, `__name__` совпадает
    с исходной функцией.

## Задание 4. Typing · текст *(обязательно)*

8–10 предложений:

1. Зачем аннотации, если `python` их не принуждает.
2. Чем `Protocol` удобнее «общего базового класса» для теста с фейком.
3. Почему `tags: list[str] = []` в dataclass плохо.

??? warning "Разбор · задание 4 · не открывать до своей попытки"

    Аннотации нужны не интерпретатору. Обычный запуск `python` их почти не
    читает: функцию с аргументом `int` можно вызвать со строкой, и скрипт
    пойдёт дальше, пока не упадёт уже внутри. Аннотации — договор для человека
    и для проверки типов до запуска (Pyright, mypy). Ошибку вида «сюда приехала
    строка вместо числа» видно в редакторе, а не в проде.

    `Protocol` описывает, какие поля или методы должны быть на объекте. Если
    они есть, тип подходит, даже без общего предка. Фейку комнаты в тесте
    достаточно поля `capacity`: наследовать абстрактный базовый класс ради
    одной проверки не нужно. Общий ABC заставил бы фейк встать в иерархию.

    `tags: list[str] = []` создаёт список один раз, когда класс загружают.
    Все комнаты без явных тегов получают один и тот же список. Дописали тег
    одной — он появился у остальных. Для нового списка на каждый объект нужен
    `field(default_factory=list)`. Для тегов, которые не должны меняться,
    лучше сразу кортеж: `tuple[str, ...] = ()`.

## Задание 5. Разбор чужого кода *(обязательно)*

```python
@dataclass
class Cart:
    items: list[str] = []

    @staticmethod
    def from_json(data: dict) -> "Cart":
        return Cart(data["items"])
```

Что ломается (2+ проблемы)? Исправьте + 5–7 предложений почему.
Подсказка: default, staticmethod vs classmethod.

??? warning "Разбор · задание 5 · не открывать до своей попытки"

    Общий `[]` — тот же баг, что у тегов комнаты: `Cart()` без аргументов
    делит один список между всеми такими корзинами.

    `@staticmethod` не получает ни объект, ни класс. Внутри зашито имя `Cart`,
    поэтому `SpecialCart.from_json(...)` вернёт базовый `Cart`, а не наследника.
    Это не «метод конкретного экземпляра»: экземпляра тут нет вообще.
    `@classmethod` и `return cls(...)` подставляют класс, у которого метод
    вызвали.

    Значение по умолчанию у поля и ключ в JSON — разные договоры.
    `default_factory` не делает `'items'` необязательным в словаре. Фабрика
    может по-прежнему требовать `data["items"]`. Зато `Cart()` без аргументов
    получит свой новый список.

    Именованный аргумент `items=` показывает, в какое поле что кладётся, если
    набор полей класса изменится.

    ```python
    from dataclasses import dataclass, field


    @dataclass
    class Cart:
        items: list[str] = field(default_factory=list)

        @classmethod
        def from_json(cls, data: dict) -> "Cart":
            return cls(items=data["items"])
    ```

    Если поле решите сделать кортежем, список из JSON оберните в `tuple(...)`.
    Датакласс сам список в кортеж не превращает. Аннотация кортежа любой
    длины — `tuple[str, ...]`.
