# 01 · dataclass · frozen · slots

**Мост:** цикл из M0.5 учит начинать с примеров. Здесь первый «пример» домена —
объекты комнаты и запроса, без которых не о чем говорить в Harbor.

**Вопрос сюжета:** как представить переговорку и запрос на бронь так, чтобы
не писать руками `__init__`/`__repr__` и не словить общий мутабельный default?

### С собесов

«Что такое dataclass?», «чем frozen отличается», «можно ли dataclass ключом
dict», «slots зачем». Редко просят написать декоратор `@dataclass` с нуля —
ждут, когда брать и какие грабли.

---

## Словарь

| Термин | English | На пальцах |
|--------|---------|------------|
| датакласс | dataclass | Класс под данные: поля в аннотациях, шаблонный код пишет Python |
| поле | field | Атрибут с типом и опциями (`default`, `default_factory`) |
| замороженный | frozen | После создания поля нельзя менять |
| слоты | `__slots__` | Жёсткий список имён атрибутов; меньше памяти |
| DTO | data transfer object | «Перенести данные», без жирной бизнес-логики |

---

## Под капотом (модель)

Обычный класс с полями вы пишете руками: конструктор, красивая печать,
сравнение «равны ли два объекта». Датакласс — договор с Python: вы
перечисляете поля и типы, а декоратор `@dataclass` **генерирует** эти методы
за вас.

Интерпретатор по-прежнему **не проверяет** типы в рантайме. Аннотации здесь —
подсказка генератору и читателю. Получается обычный класс: у экземпляра есть
атрибуты, их можно читать (а без `frozen` — и менять).

Отдельно запомните два флага:

- `frozen=True` подменяет присваивание в поля на ошибку: снаружи объект
  выглядит как снимок, который нельзя «подкрутить».
- `default_factory` вызывается **на каждый** новый экземпляр. Поэтому новый
  список тегов не оказывается общим на все комнаты сразу (см. ниже).

## Руками → принято

**Руками** (идея — что пришлось бы писать без декоратора):

```python
class BookingRequestManual:
    def __init__(self, guest_count: int, duration_minutes: int) -> None:
        self.guest_count = guest_count
        self.duration_minutes = duration_minutes

    def __repr__(self) -> str:
        return (
            f"BookingRequestManual({self.guest_count!r}, "
            f"{self.duration_minutes!r})"
        )
```

**Принято:**

```python
from dataclasses import dataclass


@dataclass
class BookingRequest:
    guest_count: int
    duration_minutes: int


# вход
req = BookingRequest(2, 60)
# выход
assert req.guest_count == 2 and req.duration_minutes == 60
print(req)  # BookingRequest(guest_count=2, duration_minutes=60)
```

Логику «какую комнату выбрать» в dataclass не кладите. Датакласс держит
данные; решение — отдельные функции или сервис. Иначе модель превращается в
свалку и её тяжело тестировать.

## default и default_factory

Иногда у поля есть значение «если не передали». Для чисел и строк достаточно
обычного default. Для списка или словаря так делать **нельзя**.

```python
from dataclasses import dataclass, field


@dataclass
class MeetingRoom:
    id: str
    capacity: int
    tags: list[str] = field(default_factory=list)
```

**Вход:** `MeetingRoom("r1", 2)` → у комнаты свой пустой `tags == []`.

**Почему не `tags: list[str] = []`?** Выражение `[]` в заголовке класса
создаётся **один раз**, когда класс загружают. Все экземпляры без явного
`tags` получили **один и тот же** список в памяти. Добавили тег одной
комнате — он внезапно появился у другой. `default_factory=list` каждый раз
вызывает `list()` заново и даёт свежий контейнер.

В Harbor для тегов удобств часто лучше сразу `tuple[str, ...] = ()`: кортеж
нельзя «дописать» на месте, меньше сюрпризов. См. домашку.

## frozen — когда и зачем

```python
@dataclass(frozen=True)
class MeetingRoomId:
    value: str


rid = MeetingRoomId("A101")
# rid.value = "B"  # FrozenInstanceError — поле менять нельзя
```

**Неизменяемость.** После создания объект — снимок. Это удобно для id комнаты,
ключа кэша, «запроса как его приняли»: никто по пути не подменит поле молча.

**Хешируемость (`__hash__`).** Раз содержимое гарантированно не изменится,
Python может построить для объекта устойчивый хеш и считать его пригодным для
`set` и для ключей `dict`. Обычный (не frozen) датакласс так по умолчанию
не умеет: меняющиеся поля сделали бы ключ ненадёжным — положили в словарь,
потом изменили поле, и объект «потерялся» по старому хешу.

Ограничение: внутри frozen все поля, от которых считается хеш, тоже должны
быть неизменяемыми по смыслу. Если положить `list` и потом сделать
`room.tags.append("x")`, снаружи экземпляр «заморожен», а содержимое списка
уже другое. Хеш больше не отражает реальность — контракт `dict`/`set`
ломается. Для таких данных берите `tuple` или не кладите мутабельное в frozen.

**Сюжет Harbor:** id комнаты и снимок запроса — frozen DTO; занятость по
времени живёт в хранилище броней, а не в «вечном» объекте комнаты.

## slots (3.10+)

```python
@dataclass(slots=True)
class Point:
    x: float
    y: float
```

Обычный экземпляр хранит атрибуты в словаре `__dict__`: гибко, но на каждый
объект есть накладные расходы. `slots=True` говорит: набор имён полей
известен заранее, отдельный `__dict__` не нужен. На миллионах мелких объектов
это экономит память; заодно нельзя случайно навесить `point.foo = 1` —
опечатка в имени сразу видна.

Для маленького Harbor флаг не обязателен, но на собесе полезно сказать
зачем он. Связка `frozen=True, slots=True` — привычный паттерн жёстких DTO.

## До / после

```python
# BAD — общий список на всех, кто не передал features
class Room:
    def __init__(self, name: str, features: list[str] = []):
        self.name = name
        self.features = features


# GOOD — новый список на каждый экземпляр
@dataclass
class Room:
    name: str
    features: list[str] = field(default_factory=list)
```

---

## Применение

- Тело JSON → dataclass (позже pydantic в M7; идея «поля = контракт» та же).
- Ключ кэша: frozen dataclass из параметров запроса.
- Harbor: `MeetingRoom`, `BookingRequest` в домене.

## Мини-голос

> Dataclass убирает шаблонный код полей. Для list/dict — только
> default_factory. Frozen — снимок и при хешируемых полях ключ dict/set.
> Slots — память и запрет лишних атрибутов. Логику брони в dataclass не прятать.
