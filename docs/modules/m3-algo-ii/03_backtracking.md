# 03 · Перебор с откатом

**Мост:** BFS и DFS из [предыдущей главы](./02_bfs_dfs.md) ходили по уже
существующему плану. Иногда граф заранее не дан: каждая вершина возникает
из очередного выбора — взять комнату, назначить слот, поставить символ.
Здесь DFS станет обходом дерева частичных решений.

**Вопрос сюжета:** как попробовать вариант, углубиться и полностью отменить
его, если продолжение не подходит?

### С собесов

Обычно спрашивают: «Чем backtracking отличается от полного перебора?»,
«Где состояние?», «Где откат?» и «Почему отсечение корректно?». Слабый
ответ — показать рекурсию и назвать её backtracking. Рекурсия лишь хранит
возврат; суть метода в симметрии **выбрал → исследовал → отменил** и в
доказуемом отказе от бесполезной ветки.

---

## Словарь

| Термин | English | На пальцах |
|--------|---------|------------|
| перебор с откатом | backtracking | Строим решение по частям; неудачную часть снимаем и пробуем следующую |
| состояние | state | Всё, что описывает частичное решение: выбранные индексы, сумма, занятые слоты |
| выбор | choice | Один допустимый следующий шаг из текущего состояния |
| дерево решений | decision tree | Корень — пустое решение, ребро — выбор, вершина — получившееся частичное решение |
| базовый случай | base case | Условие, при котором решение найдено или продолжать уже нельзя |
| откат | undo / unchoose | Точное обращение последнего изменения состояния |
| отсечение | pruning | Отказ от всей ветки, если доказано, что решения внутри быть не может |

---

## Модель: DFS по решениям, которых ещё нет

Возьмём учебное правило Harbor: из комнат вместимостью `[4, 3, 2]` надо
выбрать разные комнаты ровно на 6 мест. В реальном продукте обычно разрешён
запас мест; точное равенство здесь специально создаёт маленькую задачу
выбора.

Каждая вершина дерева хранит текущую сумму и путь выбранных индексов:

```text
                         сумма 0, []
                       /              \
             взять 0 /                  \ не брать 0
                   /                      \
          сумма 4, [0]                 сумма 0, []
             /       \
   взять 1 /           \ взять 2
         /               \
 сумма 7, [0,1]       сумма 6, [0,2]
    ОТСЕЧЬ                УСПЕХ
```

В коде ветка «не брать индекс 0» часто не написана отдельным вызовом.
Цикл просто переходит к следующему кандидату с тем же путём. Но мысленно
дерево остаётся тем же: для каждого элемента есть решения, где он выбран,
и решения, где пропущен.

Каркас метода всегда задаётся четырьмя вопросами:

1. **Состояние:** что уже выбрано и какие свойства этого выбора накоплены?
2. **Выборы:** какие кандидаты можно добавить следующими?
3. **Цель:** когда частичный ответ становится готовым?
4. **Отсечение:** по какому доказуемому признаку продолжение невозможно?

Если один пункт нельзя сформулировать словами, рекурсивный код будет набором
случайных условий.

---

## Выбрать → исследовать → отменить

Путь удобно хранить одним изменяемым списком:

```text
path.append(choice)   # выбрать
search(...)           # исследовать продолжение
path.pop()             # отменить именно этот выбор
```

`append` и `pop` должны быть парой на каждой неуспешной ветке. Если забыть
`pop`, следующий кандидат увидит комнату из предыдущей попытки, и две разные
ветки дерева склеятся в несуществующее решение. Если сделать два `pop`,
алгоритм снимет ещё и выбор родительского уровня.

Один список экономит копии на каждом шаге, но готовый ответ надо отделить от
рабочего состояния через `path.copy()`. Иначе дальнейшие откаты могут
изменить уже сохранённый результат.

---

## Какие отсечения здесь честные

Предположим, все вместимости — положительные числа, а нужна точная сумма.
Тогда верны два отсечения:

- если текущая сумма больше цели, добавление положительных чисел уже не
  уменьшит её;
- если текущая сумма плюс **все** оставшиеся вместимости меньше цели, даже
  самый щедрый остаток не спасёт ветку.

Первое отсечение станет неверным, если разрешить отрицательные числа:
после суммы 8 ещё может встретиться `-2` и дать цель 6. Правило отсечения
обязано опираться на контракт, а не на то, что сработало в одном примере.

Для второго правила заранее посчитаем суффиксные суммы:
`suffix[i]` — сумма вместимостей от `i` до конца. Это O(n) подготовки и
O(1) на проверку ветки.

---

## Реализация с входом и выходом

```python
def select_exact_capacity(
    capacities: list[int],
    target: int,
) -> list[int] | None:
    if target < 0 or any(capacity <= 0 for capacity in capacities):
        raise ValueError("capacities must be positive; target non-negative")

    suffix = [0] * (len(capacities) + 1)
    for index in range(len(capacities) - 1, -1, -1):
        suffix[index] = suffix[index + 1] + capacities[index]

    path: list[int] = []

    def search(start: int, total: int) -> list[int] | None:
        if total == target:
            return path.copy()
        if total > target:
            return None
        if total + suffix[start] < target:
            return None

        for index in range(start, len(capacities)):
            path.append(index)
            result = search(index + 1, total + capacities[index])
            if result is not None:
                return result
            path.pop()

        return None

    return search(start=0, total=0)


assert select_exact_capacity([4, 3, 2], 6) == [0, 2]
assert select_exact_capacity([5, 3], 4) is None
assert select_exact_capacity([5, 3], 0) == []
```

Параметр `start` не даёт повторно использовать одну комнату и не создаёт
перестановки одного набора. Без него наборы `[0, 2]` и `[2, 0]` выглядели
бы разными ветками, хотя комнаты те же, а один индекс мог бы выбираться
несколько раз.

На успешной ветке функция сразу возвращает отдельную копию пути. На
неуспешной ветке управление обязательно доходит до `path.pop()`, поэтому
состояние родителя восстанавливается перед следующим кандидатом.

---

## Разобранный сухой прогон

Вход: `capacities = [4, 3, 2]`, `target = 6`.

| Вызов | `path` | `total` | Что происходит |
|-------|--------|---------|----------------|
| `search(0, 0)` | `[]` | 0 | выбрать индекс 0 |
| `search(1, 4)` | `[0]` | 4 | сначала выбрать индекс 1 |
| `search(2, 7)` | `[0, 1]` | 7 | сумма выше 6: отсечь |
| возврат к `search(1, 4)` | `[0]` | 4 | `pop()` снял индекс 1 |
| `search(3, 6)` | `[0, 2]` | 6 | цель достигнута, вернуть копию |

Важный момент — строка после отсечения. Ветка `[0, 1]` не просто закончилась:
индекс 1 был снят. Поэтому следующий выбор строит `[0, 2]`, а не ошибочный
путь `[0, 1, 2]`.

---

## Цена метода

У `n` элементов до `2^n` подмножеств. В худшем случае backtracking всё
равно посетит экспоненциальное число состояний. Отсечения могут резко
сократить конкретный поиск, но не превращают метод автоматически в
полиномиальный.

Стек рекурсии и путь занимают O(n). Суффиксные суммы тоже O(n). Если
собирать **все** решения, память дополнительно зависит от размера вывода:
экспоненциальный список ответов нельзя назвать O(n), даже если рабочий путь
один.

Эта честная оценка важнее фразы «с pruning быстро». На двадцати вариантах
перебор может быть приемлем, на сотнях без особой структуры — уже нет.

## Когда backtracking не нужен

- Если надо выбрать любую комнату `capacity >= guests`, достаточно одного
  прохода. Дерева решений нет.
- Если доказано, что локально лучший выбор всегда ведёт к глобальному
  ответу, подойдёт жадный алгоритм. Само слово «жадный» доказательством не
  является.
- Если одинаковые подзадачи повторяются много раз, позже может помочь
  динамическое программирование: оно сохраняет уже вычисленные ответы.
- Большое промышленное расписание с множеством ограничений обычно требует
  отдельной модели и специализированного решателя. Учебный откат не надо
  выдавать за готовый планировщик Harbor.

## Упражнение в главе

Для `capacities = [5, 4, 3, 2]`, `target = 7`:

1. Нарисуйте ветку, в которой сначала берётся индекс 0. Отметьте, где сумма
   становится больше цели и где обязателен `pop`.
2. Запишите первые пять вызовов `search(start, total)` до найденного ответа.
3. Скажите вслух, почему отсечение `total > target` верно для этого контракта
   и стало бы неверным при вместимости `-2`.
4. Не запуская код, предскажите результат по индексам.

Самопроверка: попытки `[0, 1]` и `[0, 2]` отсекаются с суммами 9 и 8;
`[0, 3]` даёт 7. После каждой неудачи последний индекс снимается.

## Harbor и интервью

- Подобрать небольшой набор комнат под точное учебное ограничение —
  backtracking по индексам.
- Назначить несколько встреч разным комнатам без пересечений — дерево, где
  уровень соответствует встрече, а выбор — совместимой комнате.
- Проверка пересечения интервалов может стать отсечением, если уже выбранная
  бронь делает продолжение невозможным.
- На интервью до кода назовите состояние, варианты, цель и отсечение.
- Для реального Harbor сначала оцените размер входа: правильный
  экспоненциальный алгоритм всё равно может быть непригоден продукту.

## Частые ошибки

- Называть любую рекурсию backtracking, хотя состояние не меняется и не
  откатывается.
- Забыть `pop()` или выполнить его не на каждой неуспешной ветке.
- Вернуть рабочий `path` без копии и затем изменить сохранённый ответ.
- Использовать недоказанное отсечение и потерять существующее решение.
- Генерировать перестановки, когда задача спрашивает наборы.
- Скрыть экспоненту словами «после pruning обычно быстро».

## Мини-голос

> Backtracking — это DFS по дереву частичных решений.
> Я называю состояние, варианты, цель и доказуемое отсечение.
> Каждый выбор делаю через `append`, а после неудачи симметрично отменяю
> через `pop`.
> Готовый путь копирую, потому что рабочий список продолжает меняться.
> В худшем случае перебор остаётся O(2^n), даже с хорошими отсечениями.
