# 02 · Обход в ширину и в глубину

**Мост:** список смежности из [предыдущей главы](./01_graphs.md) отвечает,
кто сосед площадки. Но он не задаёт порядок движения и не мешает снова
зайти в ту же вершину по циклу. Здесь появятся два порядка обхода; дальше
похожий DFS станет каркасом перебора вариантов.

**Вопрос сюжета:** когда идти «сначала ко всем ближайшим», а когда —
«по одному коридору до упора»?

### С собесов

Типовые вопросы: «BFS или DFS?», «Где очередь, где стек?», «Почему нужен
`visited`?», «Почему BFS находит кратчайший путь?» и «Что меняется у
взвешенного графа?». Частый провал — назвать BFS и написать очередь, но
отмечать вершину посещённой слишком поздно. Тогда одна площадка попадает в
очередь много раз, а родитель кратчайшего пути может быть перезаписан.

---

## Словарь

| Термин | English | На пальцах |
|--------|---------|------------|
| обход в ширину | breadth-first search, BFS | Сначала вершины в одном переходе от старта, затем в двух и так далее |
| обход в глубину | depth-first search, DFS | Идём по выбранной ветке до упора, затем возвращаемся к развилке |
| очередь | queue | Первый добавленный элемент выходит первым: FIFO |
| стек | stack | Последний добавленный элемент выходит первым: LIFO |
| посещённые | visited | Вершины, уже взятые в работу или поставленные в неё |
| фронт обхода | frontier | Вершины, найденные, но ещё не обработанные |
| родитель | parent | Вершина, из которой мы впервые пришли; по родителям восстанавливают путь |
| невзвешенный граф | unweighted graph | Каждое ребро считается одним одинаковым переходом |

---

## Один план, два порядка

Будем обходить такой план Harbor; соседи в списках записаны слева направо:

```text
        [C]
         |
[R]-----[A]
 |       |
[B]-----[D]-----[E]
```

```python
graph: dict[str, list[str]] = {
    "R": ["A", "B"],
    "A": ["R", "C", "D"],
    "B": ["R", "D"],
    "C": ["A"],
    "D": ["A", "B", "E"],
    "E": ["D"],
}
```

Из `R` до `A` и `B` одна дверь, до `C` и `D` — две, до `E` — три. Эти
слои существуют относительно выбранного старта; если начать из `E`, номера
изменятся.

---

## BFS: очередь сохраняет слои

BFS кладёт старт в очередь. Затем повторяет один и тот же шаг: забирает
вершину с головы, рассматривает её соседей и добавляет в хвост ещё не
виденных. Очередь гарантирует, что все вершины расстояния `d` будут
обработаны раньше вершин расстояния `d + 1`.

```text
слой 0: R
слой 1: A, B
слой 2: C, D
слой 3: E

очередь: [раньше найденные ... позже найденные]
          ^ забираем отсюда          добавляем сюда ^
```

Отсюда следует кратчайший путь **по числу рёбер**. Когда вершина впервые
обнаружена, путь до неё пришёл из самого раннего возможного слоя. Более
короткий путь уже должен был бы обнаружить её раньше.

Это утверждение ломается, если рёбра имеют разную цену. Два коридора по
одной минуте могут быть быстрее одного длинного перехода на десять минут,
хотя рёбер больше. Обычный BFS минимизирует число дверей, а не минуты,
стоимость или расстояние.

### Почему отмечают при добавлении

Вершину помечают посещённой, когда кладут в очередь, а не когда достают.
На плане выше `D` соседствует и с `A`, и с `B`. После обработки `A` вершина
`D` уже стоит в очереди. Если до обработки `D` считать её «непосещённой»,
обработка `B` положит `D` второй раз. На плотном графе число дублей быстро
растёт.

Словарь `parent` может одновременно играть роль `visited`: наличие ключа
означает, что вершина уже обнаружена.

```python
from collections import deque


def shortest_path(
    graph: dict[str, list[str]],
    start: str,
    target: str,
) -> list[str] | None:
    if start not in graph or target not in graph:
        return None

    queue = deque([start])
    parent: dict[str, str | None] = {start: None}

    while queue:
        current = queue.popleft()
        if current == target:
            break

        for neighbor in graph[current]:
            if neighbor in parent:
                continue
            parent[neighbor] = current
            queue.append(neighbor)
    else:
        return None

    path: list[str] = []
    current: str | None = target
    while current is not None:
        path.append(current)
        current = parent[current]

    path.reverse()
    return path


assert shortest_path(graph, "R", "E") == ["R", "A", "D", "E"]
assert shortest_path(graph, "C", "B") == ["C", "A", "R", "B"]
assert shortest_path(graph, "R", "missing") is None
```

`deque.popleft()` забирает голову за O(1). У обычного списка `pop(0)`
после удаления сдвигает остальные элементы и стоит O(n), поэтому очередь
обхода на нём с таким вызовом незаметно получает лишнюю работу.

### Сухой прогон BFS: `R → E`

| Очередь до шага | Достаём | Новые вершины | Родители |
|-----------------|---------|---------------|----------|
| `[R]` | `R` | `A`, `B` | `A←R`, `B←R` |
| `[A, B]` | `A` | `C`, `D` | `C←A`, `D←A` |
| `[B, C, D]` | `B` | нет: `D` уже найден | без изменений |
| `[C, D]` | `C` | нет | без изменений |
| `[D]` | `D` | `E` | `E←D` |
| `[E]` | `E` | цель | остановка |

По цепочке родителей идём назад: `E ← D ← A ← R`, затем разворачиваем и
получаем `R → A → D → E`. Путь через `B` такой же длины. Первый результат
зависит от порядка соседей, но длина остаётся минимальной.

## DFS: стек хранит незавершённые развилки

DFS выбирает первого непосещённого соседа и сразу углубляется. Когда
соседей больше нет, алгоритм возвращается к последней развилке. Возврат
происходит потому, что стек помнит незавершённый путь.

На том же графе рекурсивный DFS при заданном порядке соседей идёт так:

```text
R → A → C
        ↩ A → D → B
                  ↩ D → E

порядок первого посещения: R, A, C, D, B, E
```

Рекурсивный вызов использует стек вызовов Python:

```python
def dfs_recursive(
    graph: dict[str, list[str]],
    start: str,
) -> list[str]:
    visited: set[str] = set()
    order: list[str] = []

    def visit(vertex: str) -> None:
        visited.add(vertex)
        order.append(vertex)

        for neighbor in graph[vertex]:
            if neighbor not in visited:
                visit(neighbor)

    if start in graph:
        visit(start)
    return order


assert dfs_recursive(graph, "R") == ["R", "A", "C", "D", "B", "E"]
```

Рекурсия хорошо показывает идею «посетить вершину, затем каждого ребёнка».
Но длинная цепочка может упереться в предел глубины Python и завершиться
`RecursionError`. Для данных неизвестной глубины используют явный стек:

```python
def dfs_iterative(
    graph: dict[str, list[str]],
    start: str,
) -> list[str]:
    if start not in graph:
        return []

    stack = [start]
    visited: set[str] = set()
    order: list[str] = []

    while stack:
        vertex = stack.pop()
        if vertex in visited:
            continue

        visited.add(vertex)
        order.append(vertex)

        for neighbor in reversed(graph[vertex]):
            if neighbor not in visited:
                stack.append(neighbor)

    return order


assert dfs_iterative(graph, "R") == ["R", "A", "C", "D", "B", "E"]
```

Соседей добавляют в обратном порядке, потому что стек забирает последний
добавленный элемент. Без `reversed` обход останется корректным, но первым
пойдёт правый сосед и порядок результата изменится. Если задача спрашивает
только достижимость, это обычно неважно; если тест требует конкретный
порядок, договор надо зафиксировать.

## Зачем `visited`, даже если пример — дерево

В дереве родитель может передаваться отдельным аргументом, и алгоритм не
пойдёт назад. Но общий граф содержит циклы. Без `visited` ребро `A—R`
после перехода `R → A` снова вернёт обход в `R`, затем снова в `A` — и так
без конца.

Множество посещённых — не «ускоритель на всякий случай», а часть
корректности. Оно утверждает: каждая вершина будет принята в работу не более
одного раза. Поэтому обход списка смежности стоит O(V + E): вершины
обрабатываются по разу, а все списки соседей суммарно содержат O(E) записей
(для неориентированного графа — `2E`, что в Big O всё равно O(E)).

Дополнительная память обоих обходов — O(V) на `visited` и фронт. Форма
потребления различается: BFS может держать широкий слой целиком, DFS — длинный
путь вглубь.

---

## Как выбрать обход

**BFS** берут, когда ответ связан с минимальным числом одинаково стоящих
переходов: ближайшая зона, кратчайшая цепочка знакомств, минимальное число
преобразований. Цена — очередь широкого фронта.

**DFS** берут, когда надо полностью исследовать ветку, проверить
достижимость, обойти иерархию, найти компоненты или построить каркас
перебора. Первый найденный путь может быть длинным; DFS не обещает минимум.

Если надо просто перечислить все комнаты дерева, подходят оба. Они посетят
одни вершины, но выдадут их в разном порядке. Выбор тогда определяется
удобным порядком и ограничением памяти, а не словом «быстрее»: асимптотика
одинакова.

## Упражнение в главе

Возьмите граф:

```text
S: [A, B]
A: [S, T]
B: [S, C]
C: [B, T]
T: [A, C]
```

1. Прогоните BFS из `S` до `T`. Записывайте очередь **после каждого**
   добавления и отметьте вершину посещённой в момент добавления. Какой путь
   вернётся?
2. Прогоните рекурсивный DFS из `S` в порядке соседей из списка. Запишите
   порядок первого посещения. Гарантирует ли первый путь к `T` минимум рёбер?
3. Теперь скажите, что ребро `S—A` занимает 20 минут, а каждое другое —
   одну. Объясните вслух, почему прежний BFS отвечает на другой вопрос.

Самопроверка: BFS находит `S → A → T` длины 2. Он минимален по числу рёбер,
но стоит 21 минуту; путь `S → B → C → T` имеет 3 ребра и стоит 3 минуты.

## Harbor и интервью

- Ближайшая свободная переговорка **по числу переходов** от лифта — BFS.
- Все комнаты внутри дерева здания — DFS или BFS, если порядок не задан.
- Проверка, достижима ли закрытая зона из входа, — любой обход с `visited`.
- Длинная иерархия из внешних данных — повод предпочесть явный стек рекурсии.
- Поиск комнаты только по вместимости не является задачей графа: обычный
  список остаётся честнее.

## Частые ошибки

- Помечать вершину при извлечении из очереди и накапливать дубли.
- Использовать `list.pop(0)` как очередь и получить лишние сдвиги.
- Заявить, что BFS ищет «самый короткий» путь, не уточнив одинаковую цену
  рёбер.
- Забыть `visited`, потому что единственный тестовый пример был деревом.
- Считать первый путь DFS кратчайшим.
- Путать порядок обхода с корректностью: несколько порядков могут быть
  верными при одном и том же контракте.

## Мини-голос

> BFS держит очередь и обходит граф слоями.
> В невзвешенном графе первое обнаружение даёт минимум рёбер.
> Вершину отмечаю при добавлении, чтобы не ставить её в очередь повторно.
> DFS держит стек — явный или стек рекурсии — и идёт по ветке до упора.
> Оба обхода стоят O(V + E), но DFS не обещает кратчайший путь.
