# System design · база

Базовый язык коробок для middle-собеса. **Не** курс «спроектируй Instagram».
Полный SD — в фазе 2 после гейта.

## Когда читать

| Момент | Что |
|--------|-----|
| Конец M4 | latency / throughput, синхрон vs очередь |
| M6–M7 | данные, кэш, репликация-идея, API-граница |
| M8–M9 | поиск, доставка, compose как «коробки на ноуте» |
| Мок после M7–M8 | 20–30 мин устно по одной карточке |

Карточки: [sd-cards](./sd-cards/index.md).

## Формат ответа на собесе

1. **Требования** — функциональные + нагрузка (грубо) + что важнее: латентность
   или согласованность.
2. **Naive** — один процесс + одна БД. Где умрёт?
3. **Bottlenecks** — CPU, диск, сеть, блокировки.
4. **4–6 коробок** — клиент, API, БД, кэш/очередь/поиск по нужде.
5. **Что измерить** — p99 latency, error rate, длина очереди, hit rate кэша.

## Словарь (минимум)

| Термин | На пальцах |
|--------|------------|
| latency | Сколько ждёт один запрос |
| throughput | Сколько запросов в единицу времени |
| кэш | Быстрый слой «часто читаем»; бывает устаревшим |
| очередь | Отложить работу; сгладить пик |
| load balancer | Распределить запросы по инстансам |
| репликация | Копии данных; чтение можно масштабировать |
| шардинг | Резать данные по ключу; сложно в опеке |
| CAP / BASE | Уже в SQL-треке: компромиссы согласованности |

Связь с Harbor: переговорки — хороший **прикладной** полигон, но на моке SD
дайте **чужой** мини-кейс (карточка), не «дорисуй Harbor».
