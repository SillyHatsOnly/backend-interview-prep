# Канон источников · слои и выходы

Актуально: **ноябрь 2026**. Это не «полка must-read на 4 года», а карта
**что держит наш курс**, что сознательно отложено и чем измеряем слой.

Правило курса: **книга без бинарного выхода = декорация**. Выход — не
«прочитал», а «могу сделать / объяснить / сломать осознанно».

Каталог ID и изданий: [books.md](./books.md).
Какие главы открывать в каком модуле: [reading-map.md](./reading-map.md).

---

## 0. Зачем этот канон появился

Четыре внешних ответа на вопрос «какие книги обязательны» дали полезный
каркас, но разный масштаб:

| Ответ | Сильная сторона | Слабость для *нашего* курса |
|-------|-----------------|------------------------------|
| Google | Простые столпы (Petzold, SICP, DDIA, craft) | Листлик без ОС/тестов/чтения чужого; CLRS как рабочий текст; GoF вместо живой практики; «неделя 1 = Petzold» нереалистично |
| Claude | Педагогика слоёв + **binary exit**; Skiena > CLRS как рабочий; Legacy Code; OSTEP; что выкинуть | Часть трека (интерпретаторы, Nand2Tetris целиком) — это фаза 2, не ядро middle backend |
| ChatGPT | Полная карта профессии + стадии + AI-компетенции | ~18 «essential» книг = перегруз для 9–12 мес.; generic DB textbook не лучше нашего пути Моргунов → Art of PG |
| Grok | Устойчивый middle-канон и порядок слоёв | Слишком мягко тянет Clean Code / Code Complete в must |

**Что берём в систему курса:** идею слоёв; **рабочий текст vs справочник**;
бинарные выходы; ремесло поверх синтаксиса; DDIA как мост к данным/SD;
чтение чужого кода как центральный навык эпохи LLM; осознанные *не*-must.

**Чего не берём:** «закрыть полку = закрыть курс»; полный CS degree reading
list; замену Harbor и цикла мышлением «прочитал книгу».

## 1. Тиры (как читать каталог)

| Тир | Смысл | Правило |
|-----|--------|---------|
| **A · Ядро** | Без касания этого слоя ядро курса дырявое | Не «все страницы» — выбранные главы + практика модуля |
| **B · Спутник** | Усиливает модуль; читается рядом с домашкой | По § / главе из главы курса |
| **C · Фаза 2** | Глубина после гейта или узкий голод | Не блокирует middle-гейт |

## 2. Слои курса ↔ источники ↔ бинарный выход

Выход формулируем так, чтобы его можно было проверить вслух или кодом
за один слот. Книга — опора, не зачёт.

### L0 · Как решать задачу

| | |
|--|--|
| Модули | M0.5 |
| Опора | свой цикл курса; позже — мотивы из `pragmatic` / HtDP *как идея процесса* |
| **Выход** | Любая новая задача (алго или applied): вслух проходишь цикл без пустой тишины ≥3 мин на уточнение+примеры+brute |

### L1 · Python как материал

| | |
|--|--|
| Модули | M1, M1b |
| A/B | `typed-py`; с M1b — `oust-psd`, `feathers-legacy` (фрагменты); опц. `fluent-py` |
| **Выход** | Чужой фрагмент ~30–80 строк: инвариант, края, что сломал бы; свой код того же смысла без «вставил и не могу пересказать» |

### L2 · Алгоритмы и выбор инструмента

| | |
|--|--|
| Модули | M2–M3 |
| **A рабочий** | `skiena` — *выбор* алгоритма, каталог, war stories |
| **B справочник** | `clrs4` — доказательство / точная формулировка по нужде |
| **Выход** | На новой задаче: brute → оценка → названный приём (хеш/окно/граф/…) → код; Big O своим голосом без формулы «потому что так в клипе» |

### L3 · Машина и ОС

| | |
|--|--|
| Модули | M4a |
| A/B | `ostep` (основной голос); `csapp` выборочно; `code-petzold` фон «снять магию»; exploring-os-ru выборочно |
| C | `nand2tetris` — если захочется *собрать* машину руками |
| **Выход** | Вслух: process vs thread, FD, что такое blocking I/O; на Linux — показать `ps`/`lsof`/`strace` (или аналог) на своём мини-примере |

### L4 · Сеть и concurrency

| | |
|--|--|
| Модули | M4b |
| A/B | `kurose` — картина сверху (приложение → транспорт); `unp-stevens` — справочник сокетов; `asyncio` — Python-слой |
| **Выход** | Одна картинка вслух: сокет → TCP → HTTP → процесс/поток/async task; плюс мини-пример blocking vs async без путаницы «async = быстрее CPU» |

### L5 · Ремесло: тесты, рефакторинг, чужой код

| | |
|--|--|
| Модули | M5 (+ хвост M1b) |
| A/B | `khorikov-ut`; `refactoring`; `feathers-legacy`; `pragmatic` |
| **Выход** | На чужом каркасе с тестами: зелёный рефакторинг или новый тест ловит баг, который ты сначала назвал словами |

### L6 · Данные

| | |
|--|--|
| Модули | M6 (+ M8 минимум) |
| **A наш путь** | `morgunov-2018` → `morgunov-2025` → `art-of-pg` → PostgresPro DEV1/QPT |
| **A мост к системам** | `ddia` (после того, как SQL/txn уже не пустые слова) |
| C | `pg-inside16` |
| **Выход** | Индекс + `EXPLAIN` своими словами; lost update / уровень изоляции; зачем репликация и чем она не «бесплатный scale» (после куска `ddia`) |

### L7 · Сервис, доставка, SD

| | |
|--|--|
| Модули | M7–M10, SD-карточки |
| A/B | практика FastAPI/Harbor; `ddia` + [system-design](./system-design.md); позже `release-it` |
| C | `fsa`, `se-google`, SRE-книги Google |
| **Выход** | 4–6 коробок + bottleneck на карточке SD; Harbor: API + compose поднимаются тобой, ты объясняешь каждый слой |

### L8 · Абстракция «как учёный» (фон и фаза 2)

| | |
|--|--|
| Модули | F*, P2 |
| A фон | `sicp` ≤1 глава/мес в ядре |
| C | полный SICP; `crafting-interpreters`; MCS (дискретная математика) точечно |
| **Выход (ядро)** | Можешь разобрать *одну* идею SICP (абстракция данных / процесс vs продукт) на своём примере Harbor или алго |

### Паттерны

В ядре — `patterns-dive` (Швец), 8–12 штук с кодом. Классика GoF (`gof`) —
тир **D/C**: словарь полезен, культ — нет.

## 3. AI-реальность (без отдельной «библии Copilot»)

Книги про «как жить с автокомплитом» устаревают быстрее инструментов.
Держим **компетенции** (согласованы с [how-to-study](../plan/how-to-study.md)):

1. сформулировать задачу *до* генерации;
2. дать контекст (инвариант, края, существующий код);
3. критически прочитать чужой/сгенерированный фрагмент;
4. проверить тестом;
5. объяснить принятое вслух;
6. уметь выкинуть и переписать руками.

Отдельная книга `ai-huyen` — только если пойдёшь в *продукты на моделях*, не
как must ядра backend-ремесла.

## 4. Сознательно не раздуваем полку (тир D и отказы)

| Книга / класс | Решение курса |
|---------------|---------------|
| *Clean Code* | Не закон. Читать только рядом с `oust-psd`, споря |
| *Code Complete* | Энциклопедия-справка, не сюжет модуля |
| GoF целиком | Словарь; практика — Швец + свой код |
| CLRS как единственный учебник алго | Нет → `skiena` рабочий, `clrs4` справочник |
| Connolly/Begg «Database Systems» | Не заменяем наш Postgres-путь |
| Framework-книги года | Доки + Harbor |
| Весь Stevens / весь CSAPP / все 70 дней OS | Справочник / выборочно |
| «18 essential books» за год | Нет; тиры A/B по слоям |
