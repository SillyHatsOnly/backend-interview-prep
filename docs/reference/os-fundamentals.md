# ОС · фундамент (не только терминал)

Терминал — инструмент. Рядом нужен **каркас ОС**: процессы, память, файлы,
синхронизация. Иначе async/threads/Docker останутся магией.

## Связанный проект

Уже есть перевод курса Exploring OS:

- репо: [SillyHatsOnly/exploring-os-ru](https://github.com/SillyHatsOnly/exploring-os-ru)
- сайт: [sillyhatsonly.github.io/exploring-os-ru](https://sillyhatsonly.github.io/exploring-os-ru/)
- оригинал: ~70 дней + 12 extra (C/ядро, POSIX)

В **этом** курсе Exploring OS — **фон и справочник**, не второй полный
полугодовой трек. Берём карты тем и голос; лабораторки на C — по силам,
не гейт middle Python.

## Что обязательно связать с модулями

| Тема ОС | Зачем backend | Когда в плане |
|---------|---------------|---------------|
| Процесс / `fork` / `exec` | изоляция, воркеры gunicorn, «почему не один процесс» | до/вместе M4 |
| Потоки, scheduling | GIL vs OS-thread, preemption | M4 |
| Синхронизация, deadlock | Lock, порядок замков, Postgres locks | M4 + M6 |
| Память: stack/heap, page | OOM, copy-on-write, «где живёт объект» | M1/M4 + CSAPP выборочно |
| Файлы, FD, pipe | логи, сокет = FD, Docker volume | терминал + M9 |
| I/O, блокирующий вызов | почему `recv` стопорит поток/loop | M4 |
| Сигналы, zombie | воркеры, restart | M9 |
| Сеть на пальцах (сокет) | HTTP/async | M4/M7 |

Полные блоки Exploring OS (IPC глубоко, FS реализация, hypervisor, eBPF…) —
**optional**, не must для гейта собеса.

## Терминал (практический слой)

| Тема | Зачем |

Раз в неделю ~20 мин shell-практики. Теорию ОС — карточка + ссылка на день
exploring-os-ru (номер дня), без переписывания 70 глав сюда.

## Мини-голос

> Процесс — изоляция и своя память; поток — общая память и гонки.
> Сокет и файл — дескрипторы. Блокирующий I/O держит поток; в asyncio то же
> на уровне loop. Docker пакует процесс+зависимости; K8s размножает Pod'ы.
