# K8s · потолок курса

Кубер с нуля пугает. Для middle backend вакансий чаще нужно **понимать слова
и зачем**, а не админить кластер.

## Must (карточки + голос)

| Понятие | На пальцах |
|---------|------------|
| Pod | минимальная единица: один/несколько контейнеров |
| Deployment | желаемое число реплик Pod + rolling update |
| Service | стабильный сетевой доступ к Pod'ам |
| ConfigMap / Secret | конфиг и секреты вне образа |
| Namespace | логическая изоляция в кластере |
| Probes | liveness / readiness — когда рестартить / слать трафик |
| Ingress | вход HTTP снаружи (идея) |

Связь с уже изученным: Docker-образ → в кластере крутится как Pod;
restart policy / health — родственники того, что настроите в compose.

## Should (по желанию, ~1 выходной)

- Поставить **kind** или **minikube**
- Задеплоить свой FastAPI из M7/M9 одним Deployment + Service
- Поломать readiness и увидеть, что трафик не идёт

## Out of scope

- Операционка кластера, helm charts на проде, service mesh, операторы
- Свои контроллеры, CRD

## Мини-голос

> Приложение упаковываю в образ, в K8s кручу реплики Deployment, снаружи —
> Service. Health-пробы отделяют «процесс жив» и «готов принимать трафик».
> Глубже админить кластер не претендую.
