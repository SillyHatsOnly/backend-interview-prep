# SD-02 · Очередь уведомлений

**Когда:** после M4 (asyncio / I/O), до или вместе с «фоновыми» задачами.

## Условие

После брони переговорки нужно отправить email/push. API брони не должен
ждать SMTP. Иногда SMTP лежит; нельзя терять «отправить».

## Что ожидают

1. Требования: at-least-once ок? порядок важен? идемпотентность «не спамить».
2. Naive: в handler брони сразу `send_email` — latency и сбои убивают UX.
3. Bottleneck: внешний SMTP, ретраи, пик броней в понедельник утром.
4. Коробки: API · очередь · воркер · (БД статусов доставки).
5. Метрики: длина очереди, age сообщения, success/fail send.

Связь с курсом: идея воркера позже встретится в Go-слое Harbor; здесь —
только коробки и почему очередь, не «напиши Celery».
