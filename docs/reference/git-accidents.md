# Git · аварийные сценарии

Обычный поток (branch → commit → push → MR) — с M0. Здесь — то, что ломают
в команде.

Каждые 1–2 недели **одна** авария руками в песочнице (не в `main` курса).

## Список отработок

1. Закоммитили секрет → убрать из истории осторожно (`git filter-repo` / BFG) +
   ротация ключа; понять, почему `git rm` недостаточно.
2. Кривой force-push в shared branch — как восстановить через reflog.
3. «Оторванный» rebase: конфликты, `rebase --abort`, `rebase --continue`.
4. Случайный commit не в ту ветку — `cherry-pick` / reset аккуратно.
5. Merge commit vs squash: что видно в истории и зачем команде.
6. Откатить уже попавший в main коммит: `revert` vs `reset` (когда что).
7. Битый merge от коллеги: найти виновный файл, починить, не потерять чужие изменения.
8. Detached HEAD после checkout на тег — как не паниковать.
9. Большой бинарник в истории — почему больно и как не повторять.
10. Защита main: branch protection словами (что попросить у команды).

## Мини-голос

> В shared-ветках не force-push. Секреты из истории сами не исчезают.
> Reflog — страховка. Revert безопаснее reset на main.
